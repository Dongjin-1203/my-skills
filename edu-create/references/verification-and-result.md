# 자체 검증과 작업 결과 기록

제작한 쪽이 직접 확인하는 단계다. 자기가 만든 것을 자기가 보면 놓치는 것이 있으므로, 이 결과를 독립 검수 통과로 말하지 않는다. 확인한 것과 못 한 것을 정확히 나눠 적는 것이 이 단계의 목적이다.

## 1. 검증 항목

| 항목 | 확인 내용 | 가능한 검증 수준 |
|---|---|---|
| 합의 반영 | 블록 매핑의 모든 `확정` 항목에 반영 위치가 있다. 합의에 없는 내용이 들어가지 않았다 | 내용 검토 |
| 수준·도구·환경 | 수강생 수준에 맞는 설명 깊이, 지시한 도구가 실제로 쓰일 수 있는지, 계정·기기 조건 | 내용 검토, 시험 실행 |
| 수강생용·모범 답안 일치 | 같은 과제·자료·조건. 모범 답안이 수강생용 지시를 충족한다. 수강생용에 답안이 없다 | 내용 검토 |
| 사실·출처 | 수치·인용·이론·제도 설명이 지시문·강사 자료·**채택된 조사 결과**와 일치하고, 출처 표기가 조사 파일의 출처 목록과 같다. 조사 파일에 없는 사실이 들어가지 않았다(들어갔다면 "확인 필요" 표시) | 내용 검토, 출처 접속 확인 |
| 조사 반영 | 블록마다 '사용할 조사' 항목이 반영 위치에 연결되어 있다. 보류·미확인 항목이 쓰이지 않았다 | 내용 검토 |
| 링크·경로 | 링크 문자열과 실제 접속을 구분. 참조한 파일이 실제로 있다 | 내용 검토(문자열), 접속 확인은 별도 표기 |
| 수강생용 노출 | 발표자 노트, 댓글, 숨김 슬라이드, 검토 메모, 내부 ID, 모범 답안, 접속 키·개인 정보·개인 경로 | 내용 검토 |
| 슬라이드 화면 | 렌더링한 슬라이드로 겹침·잘림·가독성 확인. 필요한 글꼴이 이 환경에 없으면 그 영역은 미확인 | 화면 확인 |
| 활동 실행 | 도구·수식·코드가 쓰이는 활동이면 새 환경에서 처음부터 순서대로 실행. 실행 시간(측정)과 수강생 소요시간(추정)을 구분 | 시험 실행 |
| 문체·균형 | 상투적 표현, 과도한 강조, 번역투, 특정 관점의 단정 여부 | 내용 검토 |

- 검증 수준은 네 가지다: **내용 검토**(내용을 읽어 확인. 대화에 붙여넣은 텍스트나 열어 본 파일 포함), **화면 확인**(렌더링 결과 확인), **시험 실행**(이 환경에서 실제 실행), **실제 수업 환경**(수강생이 쓸 플랫폼·기기·네트워크). 수행하지 않은 수준을 수행한 것처럼 쓰지 않는다. 실제 수업 환경 검증은 대개 미검증으로 남으며 숨기지 않는다.
- 링크는 "문자열 확인"과 "실제 접속 확인"을 구분한다.
- 자동 검사를 쓸 수 있어도 후보를 뽑을 뿐이다. 후보가 없다는 것이 기준 충족을 뜻하지 않는다.
- 결과 표현: 수행했고 문제를 찾지 못했으면 "확인함(문제 없음)", 못 했으면 "미검증(이유)". 마무리 문장은 "자체 검증을 마쳤고 독립 검수는 거치지 않았다"로 쓴다.

## 2. 작업 결과 기록 형식

한 과정에 결과 기록을 하나만 쓴다. 회차가 늘면 같은 기록에 회차를 추가한다. 파일을 쓸 수 있으면 지시문이 정한 위치(없으면 수강생용 자료 밖)에 두고 위치를 알린다. 파일을 쓸 수 없는 환경이면 대화 끝에 같은 내용을 **작업 메모**로 제공하고, 강사가 보관해 다음 대화에 붙여넣도록 안내한다.

```markdown
## 작업 결과 {회차}
- 분야: {강사가 답한 분야, 수강생 구성, 지정된 인용·표기 방식}
- 대상 버전: 지시문 {버전 표기 또는 날짜} / 조사 결과 {파일 목록과 버전 라벨} / 산출물 {파일명 또는 슬라이드 범위 + 버전 라벨(v1, v2 …)}
- 변경 파일·범위: {목록. 신규/수정 구분}
- 지적 반영 (외부 검토가 있었을 때)
  | 지적 ID | 필수/선택/채택 | 반영/미반영 | 이유 | 변경 위치 |
- 검증 증거
  | 항목 | 상태 | 검증 수준 | 근거(확인한 위치·화면·파일) |
- 미검증: {항목과 이유}
- 남은 판단: {강사가 정해야 할 것}
- 상태: {진행 중 | 동결(필수 결함 해결, 버전 기록)}
```

버전 식별은 파일 해시 대신 **파일명 + 버전 라벨 + 날짜**로 한다. 같은 이름의 자료가 두 곳에 있으면 강사가 어느 쪽을 가리키는지 확인한다.

## 3. 외부 검토 결과 처리

외부 검토(다른 AI나 동료)가 오면 지적마다 다음으로 나눈다.

| 구분 | 처리 |
|---|---|
| 필수 결함: 합의 위반, 수강생용 오류, 모범 답안 노출, 사실 오류, 깨진 링크·경로, 수강생용에 내부 용어 노출 | 반영한다 |
| 강사가 채택한 개선 | 반영한다. 채택은 강사가 그렇다고 말한 경우만이다 |
| 선택 제안 | 결과 기록에 적기만 한다. 채택 전에는 반영하지 않고, 그것 때문에 다시 제작 루프를 돌리지 않는다 |

- 검토 문서가 필수·선택을 표시하지 않았으면 위 표의 필수 결함 유형에 비춰 직접 나누고 근거를 적는다. 필수 유형에 해당할 **가능성이 있는데 자료를 봐도 확인할 수 없을 때만** 강사에게 묻는다. 해당할 근거가 전혀 없으면(예: "길어 보인다") 선택 제안으로 기록하고 반영하지 않는다.
- 강사가 "나중에 생각해 볼게요"라고 한 항목은 채택이 아니다. 결과 기록에 `선택(보류)`로 적고, 이후 채택하면 그때 반영한다.
- 지적 반영 표의 구분 값은 `필수` / `선택` / `선택(채택)` / `선택(보류)` 중 하나로 적는다.
- 강사 판단을 기다리는 항목이 남아 있어도, 필수 결함이 모두 해결되었으면 **동결**한다. 동결 버전을 기록하고 기다리는 항목은 '남은 판단'에 함께 적는다. 이후 변경은 새 요청으로 받는다.
- 같은 결함이 반복해서 안 풀리거나 새 판단이 필요하면(학습목표 변경, 합의 밖 수정) 멈추고 시도한 것과 근거를 강사에게 보고한다. 반복 횟수에 고정 상한은 두지 않는다.
- 반영 결과는 지적 ID별로 `반영/미반영`과 이유를 적는다. 미반영을 숨기지 않는다.

## 4. 재개

1. 작업 메모(결과 기록의 마지막 회차), 지시문, 현재 자료를 대조한다. 강사가 메모를 주지 않았으면 메모가 없다고 말하고 지시문과 현재 자료만으로 상태를 정리해 확인을 받는다.
2. 일치하면 마지막 상태에서 이어간다. 일치하지 않거나 모르는 변경(강사가 직접 수정한 것 포함)이 있으면 **그 부분은** 수정하지 말고 차이를 먼저 보고한다. 강사의 수정은 보존한다. 강사가 고친 것인지 손상인지 구분할 수 없으면 모르는 변경으로 다룬다.
   - 불일치 부분과 무관한 작업은 계속할 수 있다.
3. "없음"은 확인한 경우에만 쓴다. 확인하지 못했으면 "미확인"이다.

## 5. 정리

제작이 끝나도 파일을 자동으로 정리·삭제하지 않는다. 필요하면 강사가 별도로 요청한다.

## 6. 종료 보고 (강사에게)

짧게 쓴다: 만든 것과 위치 / 자체 검증 결과(검증 수준 포함)와 미검증 / 남은 판단 / 다음 단계(독립 검수는 강사가 별도로 요청). 작업 과정을 되풀이해 설명하지 않는다.
