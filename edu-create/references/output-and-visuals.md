# 산출물·수강생용 표현·시각 표현 기준

## 1. 폴더와 파일

- 기본 구조: `교육 폴더/교안`, `교육 폴더/수강생 자료/활동01`, `활동02` …. 이미 지정된 위치가 있으면 그 위치를 유지한다.
- 수강생 자료 폴더에는 수강생이 읽고 쓰는 것만 둔다: 활동 안내, 사례, 워크시트, 토론 질문, 과제 안내, 필요한 데이터·자산. 형식(docx, md, xlsx, csv 등)은 과제에 맞게 고른다. 수강생이 AI 도구를 쓰는 수업이면 지시사항 중심의 빈 양식 또는 Markdown이 기본이며, 지시문에 따로 정해진 것이 있으면 그것이 우선이다. 코딩·데이터 실습이 있는 과정이면 그 형식(노트북, 스크립트 등)을 쓴다.
- 모범 답안, 평가 기준, 조사 자료, 검토 결과, 작업 기록은 수강생용 자료와 분리한다. 위치는 지시문을 따르고, 지시문에 없으면 수강생용 자료 밖에 두고 위치를 강사에게 알린다. 파일을 만들 수 없는 환경이면 제목으로 구분한다([수강생 배포용] / [강사용 — 배포 금지]).
- 기본으로 만들지 않는 것: 별도 배포 폴더, 날짜별 복제본, 중복 안내문, 강사용 진행안.
- 발표 메모가 필요하면 발표자 노트에 둔다. 수강생용으로 게시할 때 노트가 노출되는지는 정책을 확인한다. 정책을 모르면 노트에는 수강생에게 보여도 되는 내용만 쓰고 "노출 정책 확인 필요"로 보고한다.
- 강사의 원본과 강사가 수정한 파일은 보존한다. 기존 파일을 삭제하거나 덮어쓰지 않고, 같은 이름의 파일이 있으면 강사에게 알린다.

## 2. 슬라이드 제작 방식

- 지시문이 지정한 템플릿·양식·제작 방식을 우선한다. 지정 템플릿이 있으면 마스터·레이아웃·글꼴·색·로고·저작권 표기를 유지하고, 작성 안내 문구·빈 자리표시자·샘플 수치를 남기지 않는다. 템플릿의 예시 슬라이드를 통째로 넣지 않는다. 템플릿 원본은 고치지 않는다.
- 지정 방식이 없고 이 환경에 슬라이드(PPT) 제작 도구나 스킬이 있으면 그것을 쓴다.
- **파일을 만들 수 없는 환경**에서는 슬라이드별로 아래 형식의 텍스트를 제공한다. 강사가 PPT에 붙여넣거나 PPT 프로그램의 AI 기능에 넣어 쓸 수 있도록 슬라이드 경계를 분명히 한다.

```markdown
### 슬라이드 {번호}: {제목}
- 본문: (수강생 화면에 보일 문장·목록. 한 슬라이드에 한 메시지)
- 시각 자료 제안: (표, 도식, 사진 등 — 해당 없으면 생략)
- 발표자 노트: (수강생에게 보여도 되는 내용만. 강사용 발화는 별도 [강사용] 블록)
```

- 글자 크기를 줄여 넘침을 해결하지 않는다. 표현을 줄이거나 슬라이드를 나눈다. 의미가 바뀌면 강사에게 알린다.
- 한 슬라이드의 본문은 읽는 데 부담이 없는 분량으로 한다. 긴 이론 설명은 요점 + 근거 사례로 나누고, 원문 인용은 짧게 한다.

## 3. 수강생용 표현

- 내부 작업용 블록 이름, 관리 ID, 검수 메모, AI 간 전달 문구를 수강생 자료에 쓰지 않는다. 수강생에게 필요한 활동 번호(활동01 등)는 유지한다.
- 강사 발화문, 일정 종속 표현("3차시에 이어서"), 예상 진행시간, 강사·조교 운영 메모는 수강생 자료에 넣지 않는다. 학습 내용에 필요한 시간 수치(토론 제한시간이 활동의 규칙인 경우, 분석 대상 기간 등)는 남긴다.
- 근거는 **실제로 확인한 원문의 제목과 출처(저자·연도·URL 등)**로 적는다. 내부 조사 메모를 원문 출처 대신 쓰지 않는다. 확인하지 못한 출처는 "출처 확인 필요"로 표시하고 만들어 내지 않는다.
- 사실, 추정, 창작 사례, 미확인을 구분해 표시한다. 창작한 사례를 실제 기업·인물의 사례처럼 쓰지 않는다. 가상 사례는 "가상 사례"라고 밝히고 실제 기업명·인물명을 쓰지 않는다.
- 상투적 도입·맺음, 과도한 강조와 이모지, 번역투를 피한다. 문체를 다듬어도 의미는 바꾸지 않는다. 이 문체 기준은 기본값이어서, 지시문이나 강사가 채택한 개선이 다르게 정하면(예: 이모지 사용) 그것을 따르되 절제해서 쓴다. 모범 답안·내부 ID·접속 키·개인 정보의 노출 금지는 예외 없이 지킨다.
- 지시문의 차시별 시간 배분(예: 강의 25분, 토론 25분)은 제작 근거일 뿐 수강생 자료에는 쓰지 않는다.
- 활동의 모범 답안·채점 기준·정답 예시는 수강생용에 넣지 않는다. 코드·스프레드시트 실습이면 정답 코드와 저장된 실행 결과도 넣지 않는다.
- 민감한 주제(정치, 종교, 젠더, 인종, 특정 기업·개인 비판)를 다루는 사례는 지시문의 의도 범위 안에서 균형 있게 쓰고, 특정 관점을 사실처럼 단정하지 않는다.

## 4. 설명에 맞는 시각 표현

먼저 아래 표에서 설명 유형에 맞는 표현을 검토한다. 긴 글이나 복잡한 표로 대신하지 않되, 장식용 이미지를 억지로 넣지도 않는다. 그림이 이해를 돕지 않으면 넣지 않는 편이 낫다.

| 설명하려는 것 | 우선 검토할 표현 | 주의 |
|---|---|---|
| 도구·화면 조작 | 실제 캡처 | 캡처는 실제로 확보한 화면만. 확보하지 못하면 "캡처 필요"로 보고 |
| 시간에 따른 변화(사건, 역사, 정책 변천) | 타임라인 | |
| 절차·의사결정 과정 | 단계와 화살표, 순서도 | 단계 수를 줄여 한 화면에 읽히게 한다 |
| 개념 간 관계(이론, 이해관계자, 구조) | 관계도, 2×2 매트릭스, 계층도 | 항목을 5~7개 안쪽으로 |
| 항목·관점·이론 비교 | 표 | 열이 많아지면 슬라이드를 나눈다 |
| 수치 변화·구성비 | 막대·선·원 그래프 | 출처와 기준 연도를 표시. 값은 확인된 자료에서만 |
| 주체 간 주고받음(고객·기업·정부 등) | 흐름도 | |

- **실제 캡처·실제 자료와 교육용 모형을 구분한다.** 모형에는 "예시 화면" "개념도" 등으로 표시하고, 근거 없는 화면·그래프를 실제 자료처럼 그리지 않는다. 수치를 지어낸 그래프는 "예시 데이터"임을 표시한다.
- 실제 캡처를 확보할 수 없으면 기본은 "예시 화면"이라고 표시한 교육용 모형이다. "캡처 필요" 같은 빈 자리표시 상자는 최종본에 두지 않는다. 대신 어느 슬라이드를 실제 캡처로 바꿔야 하는지 보고의 '남은 판단'에 적고, 제작 상태는 `부분 완료`로 둔다.
- 저작권이 있는 이미지나 캐릭터, 로고를 임의로 쓰지 않는다. 제공 자산이 아닌 이미지는 출처와 사용 조건을 확인한 것만 쓴다.
