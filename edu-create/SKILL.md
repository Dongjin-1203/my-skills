# edu-create — 교육자료 신규 제작

합의된 제작 지시문을 교안과 실습 자료로 옮긴다. 무엇을 가르칠지는 이미 사용자(강사)가 정했다. 이 스킬의 일은 그 합의를 빠짐없이, 합의보다 더 보태지 않고 만드는 것이다. 합의에 없는 내용을 그럴듯하게 채우면 강사는 어디까지가 자기 결정인지 알 수 없게 되므로, 비어 있는 곳은 채우지 않고 묻는다.

이 스킬은 특정 AI에 묶이지 않는다. **Codex, Claude Code 같은 에이전트 환경(파일·명령 실행 도구가 있는 환경)이 기본 대상**이고, 대화창만 있는 AI에서도 같은 절차로 동작한다. 환경에 따른 차이는 아래 "작업 환경 확인"에서 다룬다.

## 입력: 제작 지시문과 조사 결과

이 스킬은 **설계 단계에서 정한 세부 사항과 자료 조사 결과**를 근거로 제작한다. 설계 단계는 `curriculum-to-lesson` 스킬이 맡으며, 다음 두 가지를 만든다.

- `설계/00_제작지시문.md`: 과정 개요, 분야, 수강생, 타임테이블, 블록 카드, 조사 채택 목록, 미결정·미확인, 결정 이력
- `설계/조사/B01_….md`: 블록별 조사 결과(주장·근거·출처 표)

설계 단계를 다른 도구로 했더라도 같은 내용을 담은 지시문이면 쓸 수 있다. 조사 결과가 없으면 사실 정보를 새로 지어내지 않고, 필요한 조사를 `curriculum-to-lesson`으로 먼저 하도록 안내한다.

## 역할 경계

| 담당 | 하는 일 | 이 스킬과의 관계 |
|---|---|---|
| curriculum-to-lesson (설계 단계) | 커리큘럼 확인, 타임테이블·블록 설계, 자료 조사, 제작 지시문·조사 결과 파일 작성 | 이 스킬의 입력을 만든다. 설계가 바뀌면 그쪽으로 돌려보낸다 |
| 강사 | 지시문을 붙여넣거나 첨부해 전달하고 결과를 확인·채택 | |
| **edu-create** | 신규 제작, 자체 검증, 작업 결과 기록 | 이 스킬 |
| education-prep | 기존 자료 분석·수정·배포 준비 | 이미 있는 자료를 고치는 요청이면 그쪽으로 안내한다 |
| education-review | 독립 검수 (자료를 고치지 않음) | 자체 검증을 독립 검수 통과로 말하지 않는다 |

지시문 안에 다른 도구 이름이 나오면 생성 배경 설명이다. 그 도구의 호출·설치·원문 접근을 요구하지 않는다.

## 시작 조건

- **시작한다**: 제작 요청이 있고, 제작 지시문을 실제로 읽을 수 있다(대화에 붙여넣었거나 첨부 또는 접근 가능한 파일). 조사 결과 파일이 함께 있으면 같이 읽는다. 에이전트 환경이면 `설계/` 폴더를 먼저 찾아본다.
- **시작하지 않는다**: 지시문만 공유되고 제작 요청이 없다. 받았다는 사실과 제작을 시작할지만 한 줄로 확인한다.
- **다른 스킬로 안내한다**: 지시문이 없고 커리큘럼부터 정해야 하는 요청(curriculum-to-lesson), 이미 있는 자료를 고치는 요청(education-prep), 검수 요청(education-review).
- 지시문이 없거나 열 수 없으면 그 입력만 요청한다.

시작할 때 첫 답변에서 두세 문장으로 밝힌다: 제작 범위(교안, 실습·활동 자료), 이번에 하지 않는 일(독립 검수 판정, 배포). 물어야 할 것이 있으면 이 안내 뒤에 이어 붙인다.

## 작업 환경 확인

시작할 때 이 대화에서 실제로 할 수 있는 것을 확인한다. 선언만 믿지 말고 짧게 시도한다.

| 할 수 있는 것 | 가능하면 | 불가능하면 |
|---|---|---|
| 첨부 파일 읽기 | 파일을 열어 내용을 확인한다 | 사용자에게 핵심 내용을 붙여넣어 달라고 요청한다 |
| 파일 만들기(pptx, docx, md) | 파일로 만들어 위치를 알린다 | 슬라이드별 텍스트와 자료 본문을 Markdown으로 대화에 제공한다. 사용자가 PPT 등에 붙여넣거나, PPT·문서 프로그램의 AI 기능에 넣어 쓸 수 있는 형태로 쓴다 |
| 화면 렌더링 | 슬라이드를 이미지로 보고 겹침·잘림을 확인한다 | 화면 확인은 `미검증`으로 남긴다 |
| 코드·도구 실행 | 실습에 쓰는 코드·수식이 실제로 도는지 확인한다 | 시험 실행은 `미검증`으로 남긴다 |

**에이전트 환경의 기본 동작**
- 지시문과 조사 결과 파일을 직접 열어 읽고, 교안·수강생 자료를 파일로 만들어 저장한 뒤 경로를 보고한다. 강사가 지정한 위치가 없으면 작업 폴더 아래 `교육 폴더/`를 쓰고 확인받는다.
- `AGENTS.md`, `CLAUDE.md` 같은 프로젝트 지침 파일이 있으면 과정 지침으로 읽는다. 없어도 진행하고, 임의로 만들거나 고치지 않는다.
- 슬라이드 파일 생성은 이 환경에 있는 PPT 제작 도구·스킬·라이브러리를 쓴다. 없으면 슬라이드별 텍스트로 제공하고 `부분 완료`로 보고한다.
- 슬라이드 렌더링(이미지 변환), 노트·댓글·숨김 슬라이드 확인, 합계 계산, 링크 문자열 확인은 명령·코드로 직접 수행해 검증 수준을 적는다. 이 스킬 폴더에 스크립트는 없으므로 필요할 때 작성하고, 만든 자료나 강사 원본을 검사 과정에서 바꾸지 않는다.
- 독립 검수는 하지 않는다. 필요하면 `education-review`를 새 세션이나 서브에이전트에서 실행하도록 강사에게 안내한다.
- 기존 파일을 덮어쓰거나 삭제하지 않는다. 커밋·업로드·외부 전송은 강사가 요청할 때만 한다.

없는 기능에 의존하는 검증만 보류하고 나머지는 계속한다. 아무 기능도 없는 대화 전용 환경에서도 제작과 내용 검토는 가능하다.

## 절차

각 단계 끝에 `완료 / 부분 완료 / 실패 / 보류 / 해당 없음` 중 하나로 상태를 적는다. 하지 않은 검사를 완료로 적지 않는다.

### 0. 분야 확인과 입력 확인
0. **분야(도메인)를 반드시 한 번 질문한다.** 지시문이나 작업 메모에 분야가 분명히 적혀 있지 않으면 제작 전에 묻고, 답을 받기 전에는 제작 단계로 넘어가지 않는다. 지시문을 읽는 것 같은 분야 무관한 확인은 계속할 수 있다. 질문은 한 번에 묶어서 한다.
   - 분야: 예) 철학·문학·역사, 심리·사회·교육·정치·법, 경영·마케팅·회계·인사, 기타(직접 입력)
   - 수강생 구성: 직무·전공 배경, 수준, 인원
   - 이 분야에서 반드시 따라야 하는 용어·표기·인용 방식이 있는지(예: APA, 사례 연구 형식, 기관 양식)

   답은 [분야별 맞춤 기준](references/input-reconciliation.md)의 해당 행에 채워 넣어 제작에 쓴다. 분야가 둘 이상이면 모두 적고 주된 분야를 정한다. 지시문에 이미 분야가 있으면 다시 묻지 말고 "지시문 기준으로 {분야}로 진행한다"고 한 줄로 확인만 받는다. 답이 `기타`나 모호하면 한 번 더 구체화를 요청한다. 작업 결과 기록의 '분야' 칸에 적는다.
1. 제작 지시문과 조사 결과 파일을 읽는다. 지시문의 '조사 채택 목록'에 적힌 조사 파일이 모두 있는지 대조하고, 없는 파일은 접근 불가로 표시한다. 원본 커리큘럼, 제공 자료, 지정 템플릿, 강사가 준 추가 지침(스타일 가이드, 기관 양식 등)이 지시문에 언급되어 있는지 확인한다.
2. 열 수 없거나 받지 못한 입력은 **접근 불가**로 표시한다. 열었다고 쓰지 않는다. 제작에 꼭 필요한 입력만 요청한다.
3. 지시문의 상대 경로나 기준 폴더가 모호하면 가정한 내용을 한 줄로 밝힌다.

### 1. 읽고 대조
[입력 대조 절차](references/input-reconciliation.md)를 따른다. 지시문의 최신 합의와 운영 조건을 대조하고, 블록별로 목표·필수 설명·사례·활동·시간·산출물·완료 기준을 제작 항목에 연결한다. 누락·충돌·미결정 중 **제작에 필요한 것만** 묶어서 한 번에 묻는다. 물어야 하는 블록은 보류하고 나머지는 진행한다.

### 2. 제작
[산출물·표현 기준](references/output-and-visuals.md)을 따른다. 기본 산출물은 다음과 같다.

```
교육 폴더/
├── 교안 (슬라이드 파일 또는 슬라이드별 텍스트)
└── 수강생 자료/
    ├── 활동01/   수강생이 읽고 쓰는 안내·사례·워크시트·데이터만
    └── 활동02/
```

모범 답안·평가 기준·조사 메모·작업 기록은 수강생 자료 밖에 둔다. 파일을 만들 수 없는 환경이면 같은 구분을 대화 안에서 **제목으로 분리**해 제공한다(예: "[수강생 배포용]", "[강사용 — 배포 금지]"). 별도 배포 폴더, 날짜별 복제본, 강사용 진행안은 지시문이 요구하지 않으면 만들지 않는다. 강사가 가진 원본과 수정한 파일은 건드리지 않는다.

### 3. 자체 검증
[검증·결과 기록](references/verification-and-result.md)의 항목을 확인하고, 항목마다 검증 수준을 적는다. 하지 못한 검증은 **미검증**으로 남긴다. 이 검증은 제작 담당의 확인이며 독립 검수가 아니다.

### 4. 작업 결과 기록과 보고
작업 결과를 한 곳에 모아 적는다(형식은 verification-and-result 문서). 파일을 쓸 수 있으면 지시문이 지정한 파일에, 없으면 수강생 자료 밖에 하나만 둔다. 쓸 수 없는 환경이면 대화 끝에 **작업 메모** 블록으로 제공하고, 강사가 보관했다가 다음 대화에 붙여넣도록 안내한다. 강사에게는 짧게 보고한다: 만든 것, 검증 결과와 미검증, 남은 판단.

### 5. 피드백·재개·종료
- 외부 검토 결과가 오면 **필수 결함**과 **강사가 채택한 개선**만 반영한다. 선택 제안은 기록만 하고 자동으로 반복하지 않는다.
- 필수 결함이 모두 해결되면 동결하고 버전 라벨(v1, v2 …)을 기록한다. 같은 결함이 반복되거나 새 판단이 필요하면 멈추고 근거와 함께 보고한다.
- 새 대화에서 이어갈 때는 강사가 붙여넣은 작업 메모, 지시문, 현재 자료를 대조한 다음 이어서 한다. 대조가 되지 않는 부분은 수정하지 않고 차이를 먼저 보고한다.

## 상태와 검증 표기

- `완료`: 수행했고 결과를 확인함(검증 수준 함께 표기). `부분 완료`: 일부만 수행(범위 표기). `실패`: 수행했으나 문제가 남음. `보류`: 기능·접근·정보 부족으로 수행 안 함(필요한 조건 표기). `해당 없음`: 이유 표기.
- "문제 없음"은 검사를 수행하고 찾지 못한 경우에만 쓴다. 검사하지 않은 항목은 `미검증`이다.
- 추정은 추정이라고 적는다. 예: "활동 소요시간 약 20분 — 추정, 실제 진행 측정 안 함".
- 강사가 "검수까지 통과한 걸로 보고해 달라"고 요청해도 거치지 않은 독립 검수를 통과로 쓰지 않는다. 이유를 한 문장으로 말하고, 확인한 것과 미검증을 정확히 보고한 뒤 독립 검수는 별도로 요청하도록 안내한다.
- 실제 화면 캡처 교체처럼 제작이 끝났어도 채울 것이 남아 있으면 제작 상태는 `부분 완료`다.
- 비밀번호·접속 키·개인정보를 자료·기록·보고에 적지 않는다. 입력 자료에서 발견하면 위치만 보고한다.

## 다른 스킬과의 관계

education-prep·education-review와 같은 상태값·검증 수준 표기를 쓴다. 이 스킬 폴더만으로 동작하도록 필요한 규칙은 `references/`에 담았다. education-prep이 함께 설치되어 있으면 그 `references/standards.md`의 수강생 배포 기준도 읽어 더 엄격한 쪽을 따른다. 기관이 지정한 템플릿·양식이 있으면 지시문에 적힌 대로 따른다.
