# education-prep — 교육자료 준비·수정

이미 있는 교육자료의 검토·수정을 처음부터 배포 준비까지 진행한다. 인문·사회·경영 등 어떤 분야의 강의에도 쓸 수 있고, 특정 AI·도구·기관에 묶이지 않는다. **Codex, Claude Code 같은 에이전트 환경(파일·명령 실행 도구가 있는 환경)이 기본 대상**이고, 대화창만 있는 AI에서도 같은 절차로 동작한다.

## 먼저 읽을 기준

이 스킬 폴더 안의 문서를 읽는다. `education-review`와 같은 기준을 쓴다.

- [교육 과정·수강생 배포 기준](references/standards.md) — 차시·시간·이월·수준·수강생용/모범 답안, 승인 권한, 배포 기준, 문체, 사실·출처 점검, 파일 형식별 점검 노트
- [입력·진행안·수정 계획·검수 요청·작업 메모 형식](references/formats.md)

기준 문서의 **[확정]**은 따르고, **[제안]**은 적용하되 강사에게 제안 상태임을 알리며, **[미결정]**은 임의로 정하지 않고 확인을 요청한다.

## 핵심 원칙

1. 원본은 수정하지 않는다. 사본에서만 수정한다. (대화 환경이면 수정한 내용을 원본과 구분되는 새 텍스트·파일로 제공한다.)
2. 승인 없이 실제 자료를 수정하지 않는다. 승인 범위 안에서는 다시 묻지 않는다. 승인된 추가·삭제는 범위 이탈이 아니다.
3. 실제로 하지 않은 검사·수정을 완료로 표시하지 않는다. 상태값은 `완료 / 부분 완료 / 실패 / 보류 / 해당 없음`이다.
4. 할 수 없는 단계만 보류하고, 독립적으로 가능한 작업은 계속한다.
5. 같은 과정을 두 곳(두 기기, 두 대화, 두 사람)에서 동시에 수정하지 않는다.
6. 특정 모델·도구·경로에 의존하지 않는다.
7. 사실·수치·인용·출처는 강사 자료에 있는 것만 근거로 삼는다. 확인하지 못한 것을 AI의 기억으로 고치지 않고 "확인 필요"로 표시한다.

## 단계 0 — 환경 확인

이 대화에서 실제로 할 수 있는 것을 짧게 시도해 확인하고 표로 보고한다. 선언만 믿지 않는다.

| 할 수 있는 것 | 가능하면 | 불가능하면 |
|---|---|---|
| 자료 읽기 (첨부·폴더) | 파일을 열어 본문·노트·댓글·숨김 슬라이드를 확인한다 | 강사에게 필요한 내용(슬라이드 텍스트, 노트, 댓글, 시간표)을 붙여넣어 달라고 요청한다. 못 받은 부분은 `미검증` |
| 파일 만들기·수정 | 사본을 만들어 수정한다 | 수정한 슬라이드·문서 내용을 Markdown 텍스트로 제공한다. 강사가 원본에 반영한다 |
| 화면 렌더링 | 슬라이드를 이미지로 보고 확인한다 | 화면 확인은 `미검증` |
| 코드·도구 실행 | 코드 실습이 있으면 실행해 확인한다 | 시험 실행은 `미검증` |

**에이전트 환경의 기본 동작**
- 과정 폴더에서 자료를 직접 열어 읽고, 원본을 복사한 사본에서 수정한 뒤 저장 위치를 보고한다. 작업 메모는 과정 폴더에 `_course-status.md`로 저장한다.
- `AGENTS.md`, `CLAUDE.md` 같은 프로젝트 지침 파일이 있으면 과정 지침으로 읽는다. 없어도 진행하고, 임의로 만들거나 고치지 않는다.
- 노트·댓글·숨김 슬라이드·링크 점검, 슬라이드 렌더링, 시간 합계 검산, 학생용·모범 답안 비교는 명령·코드로 직접 수행하고 검증 수준(내용 검토 / 화면 확인 / 시험 실행)을 적는다. 이 스킬 폴더에 스크립트는 없으므로 필요할 때 작성하되, 원본은 읽기 전용으로만 다룬다. 기계적 점검은 후보만 뽑으며 판단은 직접 한다.
- 슬라이드 서식을 유지한 수정은 이 환경의 PPT 도구·스킬·라이브러리를 쓰고, 고친 뒤 파일이 열리는지와 화면을 확인한다.
- 독립 검수는 직접 하지 않고, 검수 요청서를 만들어 `education-review`를 **작성 맥락을 공유하지 않는 새 세션이나 서브에이전트**에서 실행하도록 안내한다.
- 원본 삭제·덮어쓰기, 커밋, 업로드, 공유 링크 전달, 외부 전송은 하지 않는다. 강사가 요청할 때만 한다.

대화 전용 환경에서는 "읽기 = 붙여넣은 텍스트, 쓰기 = 텍스트로 제공"이다. 이 경우에도 진행안, 수정 계획, 승인, 수정안, 검증은 모두 가능하다. 접속 키·비밀번호를 대화나 기록에 적지 않는다.

## 단계 1 — 분야 확인, 신규 시작 또는 재개

- **분야 확인(필수, 한 번)**: 작업 메모나 요청에 분야가 분명히 적혀 있지 않으면 분석을 시작하기 전에 묻는다. 분야, 수강생 구성(직무·전공·수준·인원), 지켜야 할 용어·표기·인용 방식을 한 번에 묶어 묻는다. 이미 적혀 있으면 다시 묻지 않고 한 줄로 확인만 받는다. 답을 받기 전에는 진행안·수정 계획을 확정하지 않는다(받은 자료의 목록화처럼 분야와 무관한 일은 계속한다). 답은 [standards §14](references/standards.md)의 분야별 맞춤 기준에 채워 쓰고 작업 메모의 '분야' 칸에 적는다.
- **신규**: 최소 입력([형식 §1](references/formats.md))을 확인한다. 없는 입력은 그 입력에 의존하는 판단만 보류한다. 이 과정의 **작업 메모**([형식 §2](references/formats.md))를 만든다. 원본 자료의 이름과 확인한 버전(수정일, 라벨)을 기록한다.
- **기관·업체 지정 양식 확인**: 지정 템플릿이나 양식이 있는지 묻는다. 있으면 템플릿 파일(또는 규칙 설명)을 받아 그 범위 안에서만 수정한다. 받지 못했으면 템플릿 관련 단계만 보류하고 짐작으로 맞추지 않는다.
- **재개**(새 대화, 중단 후 복귀, 다른 기기): 강사가 붙여넣은 **작업 메모**를 읽고 현재 자료와 대조한다. 메모가 없으면 없다고 밝히고 현재 자료로 상태를 정리해 확인을 받는다. 파일이 있다는 사실이나 수정 시각만으로 최신이라고 판단하지 않는다. 메모의 승인 범위와 현재 자료가 맞는지 확인하기 전에는 수정을 시작하지 않는다. 불일치하면 수정하지 않고 먼저 보고한다. 자세한 절차는 아래 "재개 절차".

## 단계 2 — 자료 목록화·분석, 조건·원본 점검

1. 자료 목록을 만든다: 이름, 형식, 차시 대응 추정, 수강생용/모범 답안용/강사용 구분, 버전(수정일·라벨).
2. 과정 조건을 정리한다: 시간표, 차시 길이, 학습목표, 변경 가능 범위, 수강생의 AI 도구 사용 여부, 활동 환경, 수강생 수준. 없는 조건은 "미확인"으로 두고 의존하는 판단만 보류한다.
3. 원본 문제를 점검한다: 배포 기준 위반(노트·댓글·숨김 슬라이드), 수강생용·모범 답안 불일치, 선수지식 순서, 깨진 링크·누락 자료, 사실·출처 의심 지점, 기관 템플릿과의 차이.
4. 각 확인 항목에 검증 수준(내용 검토 / 화면 확인 / 시험 실행 / 실제 수업 환경)을 적는다. 키워드 검색 같은 기계적 점검은 후보만 뽑으며 판단은 직접 한다.

## 단계 3 — 전체 흐름 검토, 진행안·수정 계획

1. [형식 §3](references/formats.md)으로 **차시별 진행안(강사용)**을 작성한다. 자료 범위는 슬라이드 번호·파일명·활동 번호로 적고, 시간에는 근거를 붙인다.
2. 분량 초과·부족이면 이월안·축약안을 만든다. 변경 권한이 불명확하면 "미승인 후보"로만 둔다.
3. [형식 §4](references/formats.md)로 **수정 계획**을 작성한다. 수강생용·모범 답안 영향과 승인 필요 여부를 수정 ID별로 적는다. 기관 템플릿과의 차이도 수정 ID로 넣고, 전체 재디자인은 승인 없이 계획에 확정하지 않는다.
4. 시간 합계는 계산으로 검산한다.

## 단계 4 — 독립 검수 요청 (진행안)

1. [형식 §5](references/formats.md)로 검수 요청서를 작성한다. 검수 대상 버전, 수행한 검증과 수행하지 못한 검증을 구분해 적는다.
2. 검수 담당이 원본과 검수 대상을 **직접** 볼 수 있어야 한다. 요약본만 넘기지 않는다. 검수 담당이 같은 환경의 새 대화면 파일 위치를, 파일 접근이 없는 AI면 자료 본문을 붙여넣을 수 있게 정리해 준다.
3. 인계는 강사가 직접 한다(요청서를 검수용 새 대화나 다른 AI에 붙여넣음).
4. 자기 검토는 독립 검수를 대신하지 않는다. 독립 검수를 건너뛰고 싶다는 강사의 판단은 존중하되, 그 경우 보고서에 "독립 검수 미실시"로 적는다.

## 단계 5 — 검수 반영과 강사 승인 요청

1. 검수 결과의 지적마다 조치(수정 / 반박 + 근거 / 보류 + 이유)를 정한다.
2. 진행안과 핵심 수정 사항, 미승인 후보, 미검증 사항을 함께 강사에게 제시한다.
3. 승인되면 작업 메모 "승인" 절에 승인 ID, 날짜, 승인 대상 자료와 버전, 범위 요약, 승인 항목(항목 ID)을 적는다.

## 단계 6 — 승인된 실제 수정

1. 원본을 복사해 사본을 만들고 사본만 수정한다. 대화 환경이면 수정 결과를 새 텍스트로 제공한다.
2. 수정 대상: 슬라이드, 수강생용 활동 자료, 모범 답안, 강사용 진행안(수정된 자료 위치 반영).
3. 수강생용과 모범 답안은 짝을 맞춰 함께 수정한다. 과제가 바뀌면 모범 답안도 바꾼다.
4. 수강생이 AI 도구를 쓰는 수업의 수강생용은 지시사항 중심의 빈 양식 또는 Markdown으로 만들고, 상세도는 수준·학습목표에 맞춘다.
5. 수강생 배포 기준(standards §8~§11)을 적용한다. 학습 내용에 필요한 시간 수치와 수강생에게 필요한 활동 지시는 남긴다. 기관 템플릿 슬라이드 안의 텍스트에도 똑같이 적용한다.
6. **기관 지정 템플릿**이 있으면: 마스터·레이아웃·글꼴·색·로고·저작권 표기·출처 영역을 그대로 재사용한다. 원본 템플릿은 고치지 않는다. 작성 안내 문구, 빈 자리표시자, 예제 내용·샘플 수치를 강의 내용으로 쓰거나 남기지 않는다. 내용이 넘치면 글꼴 크기를 줄이거나 양식을 바꾸지 말고 표현을 줄이거나 슬라이드를 나누는 안을 만든다(의미가 바뀌면 승인 대상). 출처 영역에는 실제로 확인한 출처만 적는다. 확인하지 못하면 "출처 확인 필요"로 보고한다.
7. 승인 범위 안의 명확한 오류는 추가 승인 없이 고치고 다시 확인한다. 같은 실패가 반복되거나 새 판단이 필요하면 멈추고 근거와 함께 보고한다.
8. 수정할 때마다 작업 메모의 사본 버전 라벨(v1, v2 …)을 갱신한다.
9. 승인 뒤 진행안을 고치면(예: 승인된 시간 배분 조정, 승인된 슬라이드 추가·삭제와 번호 재정렬) 작업 메모 "진행안 개정" 절에 개정 ID·근거 승인 ID·**근거 항목**(그 승인의 항목 ID)·이전/새 버전·변경 내용을 한 줄 기록한다. **변경 종류가 아니라 승인 범위로 판단한다**: 승인 항목 안의 변경은 학습목표·시간 배분·이월·축약이어도 재승인 없이 반영하고, 승인 항목 밖이거나 기록이 충돌하면 멈추고 보고한다. 승인 내용 자체를 볼 수 없으면 그 범위만 "확인 불가"로 두고 무관한 작업은 계속한다.

## 단계 7 — 자체 결과 검증

다음을 확인하고 항목별 상태·검증 수준을 기록한다. 이것은 준비 담당의 확인이며 독립 검수가 아니다.

- 승인 항목이 모두 반영되었는지, 승인 범위 밖 변경이 없는지
- 배포 기준 (노트·댓글·숨김 슬라이드·링크·접속 키·모범 답안 노출을 직접 확인)
- 사실·출처: 고치거나 추가한 내용에 확인되지 않은 사실이 없는지
- 화면 잘림·겹침 (렌더링 기능이 없으면 보류)
- 기관 템플릿 준수(해당할 때): 마스터·레이아웃·브랜드 요소 유지, 글자 수 안내, 남은 안내·샘플, 출처
- 코드·도구 활동이 있으면 실행 확인 (실행 기능이 없으면 보류)
- 수강생용·모범 답안 정합성 (같은 과제, 같은 자료, 모범 답안이 수강생용 지시를 충족)
- 진행안에 적힌 자료 위치가 수정본과 맞는지

## 단계 8 — 수정본 독립 검수와 재검증

1. [형식 §5](references/formats.md)로 수정본 검수를 요청한다(승인 ID와 범위 포함).
2. 결과를 반영하고, 반영 내역을 지적 ID별로 적어 재검증을 요청한다.
3. 수정 횟수에 고정 상한을 두지 않는다. 반복 실패·새 판단은 강사에게 보고한다.

## 단계 9 — 배포본 준비

배포(수강생에게 전달, 학습 플랫폼 업로드, 공유 링크)는 강사가 직접 한다. 이 스킬은 배포할 수 있는 상태의 묶음을 정리한다.

1. 검수 결과의 '검수 대상 버전'(파일별 이름·버전·역할)을 그대로 옮겨 **배포 목록**을 만든다. 배포할 수강생용 자료만 목록에 적는다. 모범 답안은 수강생용과 섞지 않고 별도 목록으로 둔다. 강사용 진행안·작업 메모는 어떤 배포 묶음에도 넣지 않는다. **판단은 파일 이름이 아니라 검수 결과의 역할과 검수된 목록으로 한다**(standards §13).
2. 검수 판정을 확인한다. `통과`면 검수 대상 버전 그대로 배포할 수 있다. `조건부 통과`면 조건마다 강사가 명시적으로 수용했는지 작업 메모 "조건 수용"에 조건 ID별로 한 행씩 적는다. 수용은 검증이 끝났다는 뜻이 아니므로 그렇게 보고하지 않는다. `재작업 필요`면 배포 목록을 만들지 않는다.
3. 검수 뒤 고친 자료는 검수받지 않은 버전이다. 배포 목록에 넣지 말고 재검증을 받아 새 버전 라벨로 기록한다.
4. 강사에게 전달 전 확인 사항을 알린다: 배포 목록, 판정, 남은 미검증, 수강생용 슬라이드의 발표자 노트·댓글·문서 속성 정리 여부. 공유 권한과 링크 전달은 강사 몫이다.
5. 미검증·미해결 사항을 숨기거나 통과로 표시하지 않는다.

## 단계 10 — 작업 요약과 작업 메모

1. 강사에게 요약한다: 배포 목록, 버전, 검수 판정, 남은 문제, 미검증 사항, 다음 작업.
2. [형식 §2](references/formats.md)의 **작업 메모**를 갱신해 제공한다. 파일을 쓸 수 있으면 과정 폴더에 저장하고 위치를 알린다. 쓸 수 없으면 대화에 메모를 출력하고 강사가 다음 대화에 붙여넣도록 안내한다. 중단하거나 다른 대화·사람에게 넘길 때도 갱신한다.
3. 상세 로그 파일을 여러 개 만들지 않는다. 과정마다 작업 메모는 하나다.

## 재개 절차

새 대화나 다른 기기에서 이어받을 때 쓴다.

1. **기능 확인**: 단계 0을 한다.
2. **상태 읽기**: 강사가 준 작업 메모를 읽는다. 메모의 마지막 갱신 시점, 단계, 다음 작업을 정리한다.
3. **자료 대조**: 메모의 버전 표와 현재 자료를 대조한다. 이름·수정일·버전 라벨·슬라이드 수 같은 눈에 보이는 식별 정보를 쓰고, 메모와 다르거나 메모에 없는 자료는 "모르는 변경"으로 분류한다. 대조하지 못한 항목은 "미확인"이다.
4. **승인 연결 확인**: 변경 종류가 아니라 **기존 승인 범위 안인지**로 판단한다. 승인 시점 버전에서 "진행안 개정" 기록을 따라 현재 버전까지 이어지는지, 각 개정이 승인 ID와 그 승인의 항목을 인용하는지 확인한다. 승인 내용을 볼 수 없으면 확인할 수 없는 범위만 보류한다.
5. **현황 보고 후 대기 또는 재개**:
   - 자료 일치 + 승인 연결됨 + 내용 확인됨 → 승인 범위 안에서 재승인 없이 재개한다.
   - 승인 연결됨이지만 내용 확인 불가 → 그 범위만 보류하고 나머지를 진행한다.
   - 자료 불일치, 모르는 변경, 승인 연결 끊김, 승인 범위 밖 → 수정하지 않고 먼저 보고한다. 어느 쪽을 기준으로 할지는 강사가 정한다.

재개 현황 보고 형식:

```
## 재개 현황: {과정명}
- 기능 확인: 읽기 {상태} / 쓰기 {상태} / 렌더링 {상태} / 실행 {상태}
- 작업 메모: {마지막 갱신 시점, 단계 | 메모 없음}
- 자료 대조: 일치 {n} / 불일치 {n} / 메모에 없음 {n} / 미확인 {n}
- 승인 연결: {연결됨 (예: A1 → R1 → R2) | 끊김 (이유) | 승인 기록 없음 | 미확인}
- 승인 준수: {확인함 | 확인 불가 (보류 범위) | 벗어남 | 미확인}
- 모르는 변경: {목록 | 없음(확인함) | 미확인}
- 판단: 재개 가능 | 확인 필요 (이유)
- 다음 작업:
```

"없음"은 확인한 경우에만 쓴다. 확인하지 못했으면 "미확인"이다.
