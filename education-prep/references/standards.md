# 교육 과정·수강생 배포 기준 (education-prep / education-review 공통)

두 스킬이 함께 참조하는 기준이다. 두 스킬의 `references/standards.md`는 같은 내용이다. 한쪽을 고치면 다른 쪽도 같이 고친다.

표기: **[확정]** 따라야 하는 기준 / **[제안]** 적용하되 강사에게 제안 상태임을 알리는 기준 / **[미결정]** 임의로 정하지 않고 강사에게 확인하는 항목.

## 1. 적용 범위

- [확정] 대상은 **이미 있는 교육자료의 검토·수정**이다. 교안(슬라이드), 수강생용 활동·실습 자료, 모범 답안·평가 기준, 커리큘럼(시간표)을 다룬다. 신규 제작은 edu-create가 맡는다.
- [확정] 수강생 배포 기준(§8~§11)은 모든 수강생 배포 자료에 적용한다.
- [확정] 기관·업체가 지정한 템플릿이나 양식이 있으면 그 자료에만 적용한다. 지정 규칙은 강사가 알려 준 내용만 근거로 삼고 짐작으로 채우지 않는다.

## 2. 우선순위

1. 해당 과정의 실제 시간표·과정 조건·기관 요구
2. 강사가 해당 작업에서 내린 판단과 승인
3. 이 문서의 일반 기준

과정별 시간표, 변경 가능 범위, 활동 환경은 작업마다 받는 입력이다. 전역 기본값으로 임의 확정하지 않는다. [확정]

## 3. 시간 구성

- [확정] 한 차시(교시)는 보통 45~50분이다. 고정하지 않고 실제 시간표를 따른다.
- [확정] 강의(이론)와 활동(토론·실습·과제)의 비율은 과정마다 다르다. 일반적으로 5:5~6:4를 참고하되, 강의만 또는 활동만 있는 차시도 허용한다.
- [확정] 도구·코드의 **실행 시간**과 수강생의 **활동 소요시간 추정**을 구분해 적는다.
- [제안] 차시별 시간 추정에는 근거(슬라이드 수, 활동 단계 수, 토론 인원·조 구성, 실행 시간 측정 여부)를 함께 적는다. 검수자가 추정의 타당성을 판단할 수 있어야 하기 때문이다.
- [제안] 시간 합계가 차시 길이를 넘거나 크게 모자라면 검수 대상으로 표시한다. 허용 오차는 과정마다 다르므로 수치를 고정하지 않는다.
- 시간 합계는 직접 계산해 검산하고 계산에 쓴 범위를 적는다.

## 4. 분량 초과·부족

- [확정] 분량이 넘치면 **이월안** 또는 **축약안**을 제시한다.
- [확정] 커리큘럼 변경 가능 범위가 불명확하면 이월·축약·삭제는 **미승인 후보**로만 제시하고 적용하지 않는다.
- [제안] 후보마다 영향 범위(학습목표 누락 여부, 뒤 차시 선수지식 영향, 수강생용·모범 답안 수정 필요 여부)를 함께 적는다.

## 5. 수강생 수준

- [확정] 수강생 수준 정보가 있으면 참고하되, 없으면 **입문 수준**을 가정해 안내하고 가정했다고 진행안에 명시한다.
- 인문·사회·경영 수강생은 전공 배경과 실무 경험이 다양하다. 전문 용어는 처음 나올 때 설명이 있는지, 사례가 수강생 직무·관심과 닿는지를 본다.

## 6. 수강생용 자료·모범 답안

- [확정] 수강생이 AI 도구를 쓰는 수업의 활동 자료는 **지시사항 중심의 빈 양식 또는 Markdown**으로 구성한다. 단계·힌트·프롬프트 예시의 상세도는 수강생 수준과 학습목표에 맞춘다.
- [확정] AI 도구를 쓰지 않는 수업은 기존 활동 자료 형식을 확인해 그대로 따른다.
- [확정] 모범 답안·평가 기준(루브릭)·해설은 수강생용과 **별도로 관리**한다. 승인된 과제 변경에 따른 답안 수정과 두 자료의 정합성 확인까지 작업 범위에 포함한다.
- 수강생용에는 모범 답안·정답 예시·채점 기준이 섞이지 않아야 한다(§8~§11).
- 코딩·데이터 실습이 있는 과정이면 정답 코드·정답 출력·저장된 실행 결과도 같은 기준으로 수강생용에서 뺀다.

## 7. 승인과 수정 권한

- [확정] 진행안과 수정 범위를 강사가 승인하면 실제 자료(슬라이드·수강생용·모범 답안) 수정까지 수행한다.
- [확정] 승인 범위 안의 수정은 반복 승인 없이 진행한다. 승인된 추가·삭제 자체를 범위 이탈로 보지 않는다.
- [제안] 새 승인이 필요한지는 변경 종류(학습목표·시간 배분·이월·축약 등)가 아니라 **기존 승인 항목 안에 들어가는지**로 판단한다.
- [확정] 명확한 오류는 수정하고 다시 확인한다. 같은 실패가 반복되거나 새로운 판단(학습목표·제약 변경, 승인 범위 밖 수정)이 필요하면 근거와 함께 강사에게 보고한다.
- 수정 시도 횟수에 고정 상한을 두지 않는다.
- [확정] 원본은 보존하고 별도 사본에서 수정한다.

## 8. 수강생 배포: 제거하거나 고칠 내용 [확정]

| 구분 | 예 | 처리 |
|---|---|---|
| 강사 발화문·대본·진행 지시 | "여기서 ~라고 설명합니다", "이 부분은 빠르게 넘어가세요" | 제거. 수강생에게 필요한 정보면 수강생 관점 문장으로 바꾼다 |
| 일정 종속 표현 | "3차시에 이어서", "2일차에 배운", "다음 시간에" | 제거하거나 실제 개념·활동 제목으로 바꾼다 ("앞의 사례 분석 활동에서") |
| 수업·활동 예상 진행시간 | "(토론 20분)", "예상 소요: 15분" | 제거 |
| 강사·조교 역할, 내부 운영 메모 | "조교는 진도 늦은 조 확인", "시간 부족 시 생략" | 제거 |

## 9. 수강생 배포: 유지할 내용 [확정]

- 수강생에게 필요한 활동 지시(무엇을 하고, 무엇을 확인·제출하는지).
- 학습 내용 자체에 필요한 시간 수치. 예: 분석 대상 기간, 법적 기한, 회계 연도, 발표 제한시간이 활동 규칙인 경우. **시간 숫자를 기계적으로 삭제하지 않는다.**
- 내용의 정확성과 의미.

## 10. 문체 [확정]

다음을 다듬되 의미는 보존한다.

- 상투적 도입·맺음 ("이번 시간에는 ~에 대해 알아보겠습니다", "지금까지 ~를 살펴보았습니다")
- 불필요한 반복 요약
- 과도한 강조(굵게·느낌표 남발)와 이모지
- 추상적 표현, 번역투 ("~하는 것이 가능합니다", "~에 있어서")

문체 수정은 의미 변경이 아니므로 승인 범위 안에서 진행할 수 있다. 다만 용어 변경·설명 추가처럼 내용이 바뀌면 수정 계획에 적는다. [제안]

## 11. 점검 위치와 검증 수준

### 점검 위치 [확정]

화면에 보이는 곳만이 아니라 파일 안의 다음 위치를 모두 점검한다.

- **슬라이드 파일**: 본문, 발표자 노트, 댓글(메모), 숨김 슬라이드, 링크
- **문서·워크시트**: 본문, 주석·변경 추적 기록, 숨김 텍스트·숨김 시트, 문서 속성(작성자 등)
- **코드·노트북이 있으면**: 설명 셀, 코드 주석, 저장된 출력(결과·오류 메시지·경로)
- **공통**: 화면 잘림·겹침, 깨진 링크, 누락된 자료, 접속 키·비밀번호·개인정보(이메일·전화번호·개인 경로), 수강생용에 섞인 모범 답안, 기관 템플릿의 작성 안내 문구·샘플 내용

배포하지 않는 발표자 노트라도 슬라이드 파일 안에 남아 있으면 파일과 함께 전달된다. 수강생용 슬라이드에서는 노트를 비우거나 수강생용 내용만 남긴다. [제안: 노트를 전부 비울지, 수강생용 설명만 남길지는 과정별 확인 필요 — 기본값 미결정]

### 사실·출처 점검 [확정]

인문·사회·경영 자료에서는 인용문, 통계, 연구 결과, 이론·학자 이름, 법·제도 조항, 기업 사례의 수치가 핵심 내용이다. AI가 기억에 의존해 쓰거나 고치면 틀릴 위험이 크다.

- 강사 원본이나 강사가 준 자료에 있는 사실만 근거로 삼는다. 근거를 확인하지 못한 사실은 고치지 않고 "확인 필요"로 표시한다.
- 새로 추가하는 사실·수치·인용은 출처를 확인했을 때만 쓴다. 확인하지 못하면 쓰지 않거나 "출처 확인 필요"로 표시한다.
- 가상 사례를 실제 사례처럼 쓰지 않는다. 가상 사례는 가상이라고 밝힌다.

### 검증 수준 구분 [확정]

보고할 때 어떤 수준으로 확인했는지 구분한다. 수행하지 않은 수준을 수행한 것처럼 적지 않는다.

| 수준 | 의미 |
|---|---|
| 내용 검토 | 내용을 읽어 확인 (대화에 붙여넣은 텍스트, 열어 본 파일의 본문·노트·댓글·링크 문자열) |
| 화면 확인 | 렌더링한 화면으로 잘림·겹침·가독성 확인 |
| 시험 실행 | 이 환경에서 코드·도구·수식을 실제 실행 (해당 자료가 있을 때만) |
| 실제 수업 환경 검증 | 수강생이 쓸 환경(플랫폼, 기기, 네트워크, 제공 도구 계정)에서 확인 |

링크는 "문자열 확인"과 "실제 접속 확인"을 구분한다. [제안]

## 12. 파일 형식별 점검 노트

도구에 묶이지 않도록 **무엇을 어디서 확인해야 하는지**만 적는다. 파일을 열 수 없는 대화 환경이면 강사에게 해당 내용(노트, 댓글, 숨김 슬라이드 목록 등)을 붙여넣어 달라고 요청하고, 못 받은 부분은 `미검증`으로 둔다.

### 슬라이드(PPTX 등)
- 화면에 안 보이는 요소도 파일에 남아 배포된다: 발표자 노트, 댓글, 숨김 슬라이드, 슬라이드 밖에 놓인 도형, 링크.
- 슬라이드 위치는 파일 이름 번호가 아니라 **표시 순서 번호**로 보고한다.
- 텍스트 확인은 내용 검토다. 잘림·겹침·가독성은 슬라이드를 이미지로 보아야 확인할 수 있다. 못 봤으면 화면 확인은 `미검증`이다.
- 수정할 때 문단 전체를 한 번에 바꾸면 글자 서식이 사라질 수 있다. 서식을 유지하며 고치고, 고친 뒤 파일이 열리는지와 화면을 확인한다.
- 슬라이드 삭제·추가·순서 변경은 내용 수정보다 먼저 하고, 삭제 뒤 참조가 끊긴 요소가 남지 않았는지 확인한다.
- 이미지 기반 슬라이드(스캔·캡처)는 텍스트 추출이 안 될 수 있다. 이미지를 직접 보고 확인하고, 보지 못했으면 `미확인`으로 둔다.

### 문서·PDF
- PDF는 이미지 기반이라 텍스트 추출이 안 될 수 있다. 추출이 비어 있으면 대표 페이지를 직접 보고 확인한다.
- 문서에는 변경 추적, 주석, 숨김 텍스트가 남아 있을 수 있다. 수강생용 배포 전에 확인한다.

### 스프레드시트(커리큘럼·데이터)
- 병합 셀·숨김 행/열·여러 시트에 시간표가 나뉘어 있을 수 있다. 숨김 요소와 모든 시트를 확인한다.
- 시간 합계는 계산으로 검산하고 계산에 쓴 범위를 적는다.

### Markdown·텍스트 수강생용 파일
- 지시사항 중심 구성인지, 모범 답안·프롬프트 정답이 들어가 있지 않은지 확인한다.
- 상대 링크와 이미지 경로가 배포 묶음 안에서 유효한지 확인한다.

### 코드 노트북(있는 경우)
- 저장된 출력에 정답 결과·오류 메시지·개인 경로·접속 키가 남아 있을 수 있다. 수강생용은 출력을 비운다.
- 실행 검증은 새 환경에서 처음부터 순서대로 실행해 확인한다. 실행 기능이 없으면 `미검증`이다.
- 데이터·보조 파일 경로가 수강생 환경에서도 유효한지 확인한다(절대 경로, 개인 폴더 경로 주의).

## 13. 파일 역할과 배포 묶음 [제안]

배포 묶음에 넣을 수 있는지는 **파일 이름이 아니라 파일 역할과 그 버전의 검수된 목록**으로 판단한다.

- 역할: 수강생용 / 모범 답안용 / 강사용 / 관리용(작업 메모 등).
- 수강생용 묶음에는 수강생용만 넣는다. 모범 답안은 별도로 보관하며 수강생용과 섞지 않는다. 강사용 진행안과 작업 메모는 어떤 배포 묶음에도 넣지 않는다.
- 역할이 없거나 알 수 없거나, 검수 목록에 없거나, 검수 뒤 내용이 바뀐 파일은 배포하지 않는다.
- 파일 이름에 `정답`·`answer`·`강사` 등이 들어 있는지는 **참고 경고**일 뿐이다. 이름이 그래도 검수 결과상 수강생용이면 막지 않고, 이름이 평범해도 검수 결과상 강사용·모범 답안용이면 그 역할대로 다룬다.
- 패턴 기반 점검이나 키워드 검색은 후보를 뽑을 뿐이며, 문맥 판단(학습용 시간 수치인지, 수강생에게 필요한 지시인지)은 직접 한다.

## 14. 분야(도메인) 확인과 맞춤 기준 [확정]

작업을 시작할 때 **분야를 반드시 한 번 질문**해 채운다. 작업 메모나 요청에 분야가 분명히 적혀 있으면 다시 묻지 않고 한 줄로 확인만 받는다. 분야를 모르는 채로 진행안·수정 계획·검수 결과를 확정하지 않는다.

질문 내용(한 번에 묶어서): 분야, 수강생 구성(직무·전공·수준·인원), 반드시 따라야 하는 용어·표기·인용 방식(예: APA, 기관 양식).

| 분야 | 사례·자료 유형 | 근거·출처 | 활동 형식 | 특히 주의 |
|---|---|---|---|---|
| 인문(철학·문학·역사·언어) | 원문 발췌, 텍스트 읽기, 연표, 개념 지도 | 저자·판본·쪽수. 번역서는 역자 표기 | 텍스트 정독, 논증 재구성, 토론, 에세이 | 원문 인용은 짧게·정확히. 번역·해석 차이를 구분 |
| 사회(심리·사회·교육·정치·법) | 연구 결과, 사례 연구, 통계 자료, 조항·판례 | 연구자·연도·표본, 법 조항 번호, 통계 기준 연도 | 사례 분석, 토론, 설문 설계, 정책 비교 | 통계·판례·조항은 AI 기억으로 쓰거나 고치지 않는다. 관점 균형 |
| 경영(경영·마케팅·회계·인사) | 기업 사례, 재무제표, 시장 데이터, 프레임워크(SWOT 등) | 기업 공시·보고서·기사 출처와 기준 시점 | 케이스 분석, 프레임워크 적용, 의사결정 시뮬레이션, 보고서 | 실제 기업 수치는 확인된 자료만. 가상 사례는 가상 표시 |
| 기타 | 강사 답변에 따름 | 강사 답변에 따름 | 강사 답변에 따름 | |

- 표는 기본값이다. 강사가 말한 용어·방식이 우선한다. 분야가 둘 이상이면 모두 적고 주된 분야를 정한다.
- 분야 답이 `기타`이거나 모호하면 한 번 더 구체화를 요청한다.
- 분야는 작업 메모 맨 위 '분야' 칸에 적고, 진행안의 과정 조건 요약, 수정 계획의 사실·출처 점검, 검수 지적의 근거 판단에 쓴다.
