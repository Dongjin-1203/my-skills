# 입력·작업 메모·진행안·수정 계획·검수 요청 형식

표기: **[확정]** / **[제안]** / **[미결정]**.
형식은 Markdown 텍스트다. 어떤 AI든 읽고 쓸 수 있도록 특정 서비스 문법에 의존하지 않는다.

---

## 1. 최소 입력

작업 시작 시 아래를 확인한다. 필수 항목이 없어도 **그 항목에 의존하지 않는 분석은 계속**하고, 의존하는 판단만 보류한다. [확정]

| 항목 | 필수 | 없을 때 |
|---|---|---|
| 과정명 | 필수 | 강사에게 요청 |
| 분야·수강생 구성·인용/표기 방식 | 필수 | 반드시 한 번 질문해 채움(standards §14). 이미 있으면 확인만 |
| 원본 자료(슬라이드, 수강생용 활동, 모범 답안) | 필수 | 요청. 받은 자료만으로 가능한 분석 진행 |
| 기관·업체 지정 템플릿·양식 | 해당 시 | 있는지 먼저 확인. 있는데 받지 못했으면 템플릿 관련 단계만 보류 [확정] |
| 커리큘럼·시간표 | 과정별 | 없으면 교안·과정 설명으로 진행 범위를 설계 [확정] |
| 차시 구성(일차·차시·차시 길이) | 필수 | 차시 배분 보류, 자료 자체 분석은 진행 |
| 학습목표 | 필수 | 커리큘럼에서 추출. 없으면 추출안 제시 후 확인 요청 |
| 수강생의 AI 도구 사용 여부 | 필수 | 수강생용 활동 형식 결정 보류 |
| 변경 가능 범위 | 권장 | 이월·축약·삭제는 미승인 후보로만 제시 [확정] |
| 수강생 수준·직무 배경 | 권장 | 입문 수준 가정, 가정했다고 명시 [확정] |
| 활동 환경(수업 방식, 사용 도구, 계정) | 권장 | 실제 수업 환경 검증 "보류" |
| 모범 답안·평가 기준 위치 | 권장 | 정합성 확인 보류 |

## 2. 작업 메모 (과정별 1개)

작업의 현재 상태·승인·버전을 한 곳에 모은 짧은 기록이다. 새 대화나 다른 기기에서 이어받을 때 **강사가 이 메모를 붙여넣거나 첨부**해 상태를 전달한다. 대화 기록이나 AI의 기억에 의존하지 않기 위한 장치다. [확정]

- [확정] 과정별로 최소 정보만 담은 메모 **하나**만 둔다. 상세 설명은 대화나 강사의 별도 기록에 둔다.
- [확정] 이 메모는 **잠금 장치가 아니며 동시 수정을 막지 않는다.** 동시 수정 방지는 강사가 지키는 운영 규칙이다.
- [제안] 파일을 쓸 수 있으면 `_course-status.md`라는 이름으로 과정 폴더 최상위에 둔다. 쓸 수 없으면 대화에 출력하고 강사가 보관한다.
- [제안] **버전 식별**: 자료마다 `이름 + 버전 라벨(v1, v2 …) + 확인일`을 적고, 가능하면 슬라이드 수·문서 쪽수 같은 눈에 보이는 식별 정보를 덧붙인다. 파일 수정 시각만으로 같은 내용인지 판단하지 않는다. 식별 정보를 확인하지 못했으면 "미확인"으로 적는다.
- [제안] 아래 `original/`, `plan/`, `work/`, `release/` 구분은 원본 보존과 배포 묶음 분리를 위한 예시다. 기존 폴더 구조가 있으면 그 구조를 따른다.
- [제안] **승인 기록**: 승인 ID·날짜·승인 대상 진행안의 버전·승인 범위 요약·**승인 항목(항목 ID 목록)**·**승인 상세 위치**(예: "대화 중 2024-05-03 진행안 승인 메시지")를 적는다. 이유: 재개할 때 승인 범위와 자료 버전을 한 곳에서 대조해야 하기 때문이다.
- [제안] **승인 범위 내 진행안 개정 — 변경 종류가 아니라 승인 범위로 판단한다**: 승인 뒤에도 진행안은 바뀔 수 있다(예: 승인된 시간 배분 조정, 승인된 슬라이드 추가·삭제와 번호 재정렬). 이미 승인된 범위 안의 변경은 **변경 종류(학습목표·시간 배분·이월·축약 등)와 관계없이 새 승인 없이** "진행안 개정" 절에 한 줄씩 기록하고, "자료 버전"의 진행안 행은 **현재** 버전으로 갱신한다. 새 판단을 받는 경우는 (1) 승인 항목 밖의 변경, (2) 기록끼리 충돌할 때뿐이다.
  - **기준선 구분**: 승인 시점 기준선은 "승인" 절의 승인 버전, 현재 개정본은 "자료 버전"의 진행안 행이다. 재개 시 최초 승인본과 직접 비교하지 않고 승인 버전 → 개정 기록을 따라 현재 버전까지 이어지는지 확인한다. 각 개정 행은 **근거 승인 ID**와 **근거 항목**(그 승인의 "승인 항목"에 있는 ID)을 적는다.
  - **변경 유형 표기는 승인의 증거가 아니다**: `승인 항목 반영` 같은 표기만으로 승인된 내용으로 보지 않는다. 근거 항목이 실제 승인 항목에 있고, 변경 내용이 그 항목의 승인 상세에 들어가는지가 기준이다.
  - **내용 확인 칸**: `확인함`(승인 상세를 보고 변경 내용과 대조함) / `확인 불가`(승인 상세를 볼 수 없음) / `벗어남`(승인 범위 밖) / 빈 칸(미확인). 승인 상세 위치가 없으면 `확인함`을 쓰지 않는다.
  - **상세를 볼 수 없을 때**: 확인할 수 없는 범위만 보류하고 무관한 분석은 계속한다. 새 승인을 요구하지 않는다.
  - **승인 범위 밖이거나 기록이 충돌할 때**(개정 기록이 없거나 이어지지 않음, 개정 기록의 새 버전과 실제 자료가 다름, 근거 항목이 승인에 없음, `벗어남`): 수정을 재개하지 않고 먼저 보고해 강사 판단을 받는다.

```markdown
# 작업 메모: {과정명}

- 분야: {강사가 답한 분야} / 수강생 구성: {직무·전공·수준·인원} / 인용·표기 방식: {지정된 것 | 없음}
- 단계: {접수 | 조건점검 | 진행안작성 | 진행안검수 | 승인대기 | 수정중 | 수정본검수 | 반영중 | 배포준비 | 배포완료 | 중단}
- 마지막 갱신: {YYYY-MM-DD} / 갱신한 담당: {준비 | 검수} / 사용한 AI·환경: {이름 또는 "대화 전용"}
- 기능 확인: 읽기 {가능/불가} · 쓰기 {가능/불가} · 렌더링 {가능/불가} · 실행 {가능/불가}

## 자료 버전
| 구분 | 이름(위치) | 버전 라벨 | 식별 정보(슬라이드 수·쪽수·수정일 등) | 역할 | 비고 |
|---|---|---|---|---|---|
| 원본 | | | | | 수정 금지 |
| 기관 템플릿 | | | | | 있을 때만. 복사하지 않고 원본 위치만 적음 |
| 진행안 | | | | 강사용 | 승인 대상이면 승인 ID 표기 |
| 사본(작업본) | | | | | |
| 검수본 {버전} | (검수 결과의 검수 대상 버전 전부) | | | 수강생용·모범 답안용·강사용·관리용 | 검수 결과의 이름·버전·역할을 그대로 옮김 |
| 배포 목록 {버전} | | | | 수강생용·모범 답안용 | 전달할 자료만. 검수본 행과 같은 이름·버전·역할 |

## 승인
| 승인 ID | 날짜 | 승인 대상 | 승인 버전 | 승인 범위 요약 | 승인 항목 | 승인 상세 위치 | 제외·미승인 후보 |
|---|---|---|---|---|---|---|---|

## 진행안 개정
| 개정 ID | 날짜 | 근거 승인 ID | 근거 항목 | 이전 버전 | 새 버전 | 변경 내용 | 내용 확인 |
|---|---|---|---|---|---|---|---|

## 검수·배포 판정
| 배포 버전 | 검수 결과(ID) | 판정 | 미해결 높음 | 조건(ID만) |
|---|---|---|---|---|

## 조건 수용
| 배포 버전 | 검수 결과(ID) | 조건 ID | 조건 내용 | 수용 | 수용 일자 | 수용 확인 위치 |
|---|---|---|---|---|---|---|

## 미검증·남은 판단
- {항목}

## 다음 작업
- {한두 줄}
```

- 조건 수용 표는 **조건 ID마다 한 행**을 적는다. 수용 칸 값이 정확히 `수용`인 행만 수용으로 본다. 다른 배포 버전·검수 결과 ID의 수용 기록은 재사용하지 않는다. 수용은 강사가 남은 조건을 받아들인 기록이며 **조건이 뜻하는 검증이 끝났다는 뜻이 아니다.**
- 검수본 행은 검수 결과의 '검수 대상 버전'을 그대로 옮긴 것이다. 배포 목록 행은 그중 전달할 수강생용·모범 답안용만 옮긴다. 검수하지 않은 자료, 역할이 없는 자료, 검수 뒤 고친 자료는 배포 목록에 넣지 않는다. 판단 기준은 파일 이름이 아니라 **검수된 목록과 역할**이다.

## 3. 차시별 진행안 (강사용)

강사용 문서다. 발화·시간·운영 메모를 포함할 수 있으며 수강생 배포 묶음에 넣지 않는다. [확정]

```markdown
# 진행안: {과정명} — 버전 {라벨}

## 과정 조건 요약
- 시간표 / 차시 길이 / 강의:활동 비율 / 수강생의 AI 도구 사용 / 수강생 수준(가정 여부) / 변경 가능 범위 / 활동 환경
- 확인되지 않은 조건: ...

## 전체 흐름 검토
- 학습목표 ↔ 차시 연결, 선수지식 순서, 원본 문제 요약(상세는 수정 계획)

## 차시별 진행
| 일차 | 차시 | 학습목표 | 활동(강의/토론/실습/과제) | 자료 위치(슬라이드·활동 번호·파일) | 강의(분) | 활동(분) | 시간 근거 | 비고 |
|---|---|---|---|---|---|---|---|---|

## 이월·축약 후보 (미승인)
| 후보 ID | 내용 | 이유 | 영향(학습목표·선수지식·수강생용·모범 답안) |

## 확인 필요 사항
```

## 4. 수정 계획

```markdown
| 수정 ID | 대상 자료·위치 | 문제(근거) | 수정 내용 | 수강생용 영향 | 모범 답안 영향 | 승인 필요 여부 | 상태 |
|---|---|---|---|---|---|---|---|
```

- 상태는 `완료 / 부분 완료 / 실패 / 보류 / 해당 없음` 중 하나다.
- "승인 필요 여부": `승인 범위 내` / `승인 필요(새 판단)` / `미승인 후보`.
- 기관 지정 템플릿과 기존 자료의 차이(다른 마스터·레이아웃, 로고 누락, 글꼴·색 변경, 남은 안내 문구 등)도 수정 ID로 적는다. 전체 재디자인이나 대량 레이아웃 교체는 `승인 필요(새 판단)`이다. [확정: 승인 없는 전체 재디자인 금지]
- 사실·출처를 확인하지 못한 항목은 수정하지 않고 "확인 필요" 수정 ID로 남긴다.

## 5. 검수 요청 (준비 → 검수)

강사가 이 요청을 검수 담당(새 대화의 AI, 다른 AI, 동료 강사)에게 전달한다. [확정] 요청서는 안내일 뿐이며, 검수 담당은 원본과 검수 대상을 **직접** 확인한다. 파일을 열 수 없는 검수 환경이면 강사가 자료 본문을 요청서와 함께 붙여넣는다. [확정]

```markdown
# 검수 요청: {과정명} — {진행안 검수 | 수정본 검수 | 재검증}
- 요청일 / 요청 담당 / 회차: {1, 2, ...}

## 검수 자료 접근 방법
- 원본: {위치 또는 "아래에 붙여넣음"}
- 과정 조건 자료: 커리큘럼·시간표·요구사항
- 검수 대상: 자료 목록과 버전(작업 메모의 '자료 버전' 표 형식)

## 승인 범위 (수정본 검수일 때)
- 승인 ID와 범위 요약. 승인된 추가·삭제는 범위 이탈이 아님

## 준비 담당이 수행한 검증
| 항목 | 상태 | 검증 수준 | 비고 |

## 준비 담당이 수행하지 못한 검증
- 항목과 이유

## 이전 검수 결과 반영 (재검증일 때)
| 지적 ID | 조치(수정 | 반박 | 보류) | 근거·변경 위치 |

## 특히 확인 요청할 점
```

검수 결과 형식과 판정 정의(`통과 / 조건부 통과 / 재작업 필요`)는 education-review의 `references/review-checklist.md`에 있다. 준비 담당은 검수 결과의 **검수 대상 버전**(자료별 이름·버전·역할)과 **판정**, **조건 ID**를 작업 메모에 옮긴다.

## 6. 보고서·요약에 쓰는 표현

- 수행하지 않은 것을 완료로 쓰지 않는다. 검사하지 않은 항목은 `미검증`이다.
- "독립 검수 통과"는 별도의 검수 담당이 낸 판정이 있을 때만 쓴다. 자체 검증은 "자체 검증"이라고 쓴다.
- 비밀번호·접속 키·개인정보는 작업 메모·보고서에 적지 않는다. 발견하면 위치만 보고하고 값은 가려서 적는다.
