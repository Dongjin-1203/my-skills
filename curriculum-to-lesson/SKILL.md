# curriculum-to-lesson — 커리큘럼 확인·세부 설계·자료 조사

교육자가 처음 교육을 준비할 때 **무엇을, 어떤 순서와 시간으로, 어떤 근거로 가르칠지**를 정하고 그 결과를 파일로 남긴다. 이 스킬의 산출물은 두 가지다.

1. **제작 지시문**(`00_제작지시문.md`): 과정 개요, 타임테이블, 블록별 세부 내용, 결정 이력, 채택한 조사 목록
2. **블록별 조사 결과**(`조사/B01_….md` 등): 각 블록의 설명·사례·활동에 쓸 근거와 출처

`edu-create`는 이 두 가지를 입력으로 받아 교안(PPT)과 실습 자료를 만든다. 그래서 이 스킬은 정한 것과 조사한 것을 **다른 대화를 읽지 않아도 제작할 수 있는 수준**으로 남기는 것이 목표다.

특정 AI에 묶이지 않는다. **Codex, Claude Code 같은 에이전트 환경(파일·명령·웹 도구가 있는 환경)이 기본 대상**이고, 대화창만 있는 AI에서도 같은 절차로 동작한다. 환경별 차이는 아래 "환경 확인"에서 다룬다.

## 하지 않는 일

- PPT·실습 파일 제작, 독립 검수, 배포. 이 스킬을 호출했다는 이유로 자동으로 시작하지 않는다.
- 확인하지 못한 사실을 AI의 기억으로 채워 조사 결과처럼 쓰는 일. 인용·통계·이론·제도·기업 수치는 출처를 확인한 것만 "확인됨"으로 적는다.
- 강사가 정하지 않은 학습목표·시간·수준·도구를 임의로 확정하는 일.

요청 범위만큼만 한다. 블록 논의만 요청하면 논의안까지, 조사만 요청하면 조사 결과까지, 인계를 요청하면 제작 지시문까지 작성한다.

## 환경 확인

시작할 때 이 대화에서 실제로 할 수 있는 것을 짧게 시도해 확인한다.

| 할 수 있는 것 | 가능하면 | 불가능하면 |
|---|---|---|
| 자료 읽기 (첨부·폴더) | 커리큘럼·기존 자료를 열어 확인 | 강사에게 핵심 내용을 붙여넣어 달라고 요청 |
| 파일 저장 | `설계/` 폴더에 md 파일로 저장하고 위치를 알림 | 각 파일을 `파일명` 제목과 함께 코드 블록으로 대화에 제공. 강사가 같은 이름으로 저장해 보관 |
| 웹 검색·원문 열기 | 직접 조사하고 URL·확인일을 기록 | **조사 지시문**([조사 절차](references/research-protocol.md))을 작성해 검색 가능한 AI나 강사가 직접 조사하도록 넘김. 결과 md를 붙여 받으면 이어서 진행 |
| 시간 계산 도구 | 계산으로 검산 | 직접 단계별로 계산해 검산 과정을 적음 |

**에이전트 환경의 기본 동작**
- 작업 폴더에서 커리큘럼·기존 자료를 직접 읽고, 결과를 `설계/` 폴더에 md 파일로 직접 저장한 뒤 저장 위치를 보고한다. 강사가 지정한 위치가 없으면 작업 폴더 아래 `교육 폴더/설계/`를 제안하고 확인받는다.
- 프로젝트 지침 파일(`AGENTS.md`, `CLAUDE.md` 등)이 있으면 과정 지침으로 읽는다. 없어도 진행하고, 지침 파일을 임의로 만들거나 고치지 않는다.
- 웹 검색·원문 열기 도구가 있으면 직접 조사한다. 조사가 길거나 블록이 많으면 블록 단위로 서브에이전트·병렬 세션에 나눌 수 있다. 각 조사는 같은 결과 형식을 쓰고, 결과를 받은 쪽(이 스킬)이 내용을 열어 확인·채택한다.
- 시간 합계 검산 같은 반복 계산은 짧은 명령이나 코드로 해도 된다. 이 스킬 폴더에 스크립트는 없으므로 필요할 때 작성하되 강사 자료는 읽기 전용으로만 다룬다.
- 강사 원본은 수정하지 않는다. 같은 이름의 설계 파일이 있으면 덮어쓰지 말고 새 버전 라벨을 붙이거나 확인을 받는다. 커밋·업로드·외부 전송은 강사가 요청할 때만 한다.

웹 검색이 없는 환경에서는 "조사 실행"이 아니라 "조사 지시문 작성"까지가 이 스킬의 일이다. 조사를 실행하지 않았는데 실행한 것처럼 보고하지 않는다.

## 절차

각 단계 끝에 `완료 / 부분 완료 / 실패 / 보류 / 해당 없음` 중 하나로 상태를 적는다. 하지 않은 것을 완료로 적지 않는다.

### 1. 분야와 조건 확인 (필수, 한 번 질문)

**분야를 반드시 한 번 질문한다.** 이미 알려져 있으면 다시 묻지 않고 한 줄로 확인만 받는다. 아래를 한 번에 묶어 묻는다.

- 분야: 예) 철학·문학·역사, 심리·사회·교육·정치·법, 경영·마케팅·회계·인사, 기타(직접 입력)
- 수강생: 직무·전공 배경, 수준, 인원, 교육 후 가장 남기고 싶은 역량
- 시간: 총 교육 일수·시간, 시작·종료·점심·휴식
- 환경: 대면/온라인, 수강생이 쓸 도구·계정, 제공 가능한 자료
- 커리큘럼이 이미 있는지(있으면 붙여넣기·첨부), 지켜야 할 용어·표기·인용 방식(예: APA, 기관 양식)

답을 받기 전에는 블록 설계로 넘어가지 않는다. 분야 답은 [조사 절차](references/research-protocol.md)의 분야별 조사 가이드에 채워 쓰고 제작 지시문의 '분야' 칸에 적는다. 답이 `기타`나 모호하면 한 번 더 구체화를 요청한다. 없는 조건은 `미확인`으로 두고 설계에 필요한 가정만 명시한다.

### 2. 커리큘럼 확보

- **커리큘럼이 있을 때**: 원문을 직접 읽고 목표·필수 주제·활동·산출물과 위치를 뽑는다. 파일 이름이나 요약만으로 원문 확인을 대신하지 않는다. 읽지 못한 범위는 표시한다.
- **커리큘럼이 없을 때**: 질의응답으로 만든다. 한 번에 설문처럼 쏟아붓지 말고, 1단계 답을 바탕으로 **블록 구성안(제목, 한 줄 목적, 대략 시간)을 먼저 제안**하고 강사가 고치게 한다. 질문은 결과에 영향을 주는 것만 짧게 한다.
- 어느 쪽이든 최종적으로 강사가 확정한 **블록 목록**이 있어야 다음 단계로 넘어간다. 원안의 목표를 시간 확보 명목으로 임의 삭제하지 않는다.

### 3. 타임테이블

시작·종료·점심·휴식 조건으로 블록을 시간표에 배치한다. 양식은 [제작 지시문 양식](references/brief-template.md)의 '타임테이블'을 쓴다.

- 블록 총시간, 내부 활동 합계, 휴식, 미배정 시간을 각각 적고 합계와 겹침·공백을 검산한다. 차이는 "미배정" 또는 "운영 여유"로 명시하고 임의로 휴식을 끼워 넣지 않는다.
- 강의(설명·시연)와 활동(읽기·토론·실습·발표)의 시간 근거를 구분한다: 측정 / 안내 / 추정. 추정을 실제 수행시간으로 보고하지 않는다.
- 총량이 안 맞으면 이월·통합·축약 후보를 근거와 함께 제안한다. 확정은 강사 몫이다.

### 4. 블록별 세부 설계 (대화 반복)

강사가 보는 블록 순서와 속도를 따른다. 원안 기반의 구체안을 **먼저 제시하고**, 결과에 영향을 주는 미결정 사항만 짧게 논의한다. 각 블록에서 다음을 맞춰 **블록 카드**([양식](references/brief-template.md))에 채운다.

1. 목적과 원안 의미: 이 블록이 필요한 이유, 추상적 용어의 실제 뜻
2. 학생이 할 수 있게 될 일(관찰 가능한 행동)
3. 최종 산출물: 무엇을 어느 수준까지 완성하는지, 축약 완성 예시와 잘못된 예. 중간 작업물과 구분
4. 설명·사례·시연: 산출물을 만들고 판단하는 데 필요한 이론·사례, 각 항목이 필요한 이유
5. 활동(토론·실습·과제): 제공 자료, 학생 수행 순서, 확인 기준
6. 시간, 다음 블록으로 넘길 결과

설명 근거가 부족하면 조사 과제로, 산출물이 모호하면 과제 재정의로, 분량이 많으면 중복·꾸미기 축소로 돌아간다. 한 블록이 정해질 때마다 결정을 `확정 / 제안 / 미확인`으로 기록한다. 전체 방향에 대한 동의를 세부 시간·활동 전체의 승인으로 확대하지 않는다.

### 5. 조사 과제 도출과 실행

블록 카드에서 "근거가 필요한 것"을 모아 **조사 과제 목록**을 만든다. 상세는 [조사 절차](references/research-protocol.md)를 따른다.

- 조사 과제는 설명 근거 / 사례 / 활동 자료 / 용어·정의 / 도구·환경 조건 중 무엇을 보완하는지, 어느 블록에 쓰이는지를 정한다.
- 웹 검색이 가능하면 직접 조사해 결과를 **블록별 md 파일**로 저장한다. 불가능하면 조사 지시문을 작성한다.
- 강사가 이미 가진 자료(교재, 논문, 기사, 사내 자료)가 있으면 그것을 1순위 근거로 쓴다. 강사에게 파일이나 본문을 달라고 요청한다.
- 결과는 사실 / 출처의 주장 / 해석 / 교육용 창작을 구분해 적는다.

### 6. 조사 결과 확인과 채택

회수한 결과의 실제 내용을 열어 질문에 답했는지, 핵심 원문이 있는지 확인한다. 항목마다 `채택 / 수정 / 보류`를 정하고 적용 블록·위치를 연결한다. 확인하지 못한 핵심 근거는 보류하고, 영향받지 않는 설계는 계속한다. 조사 보고서를 그대로 교안으로 복사하지 않는다. 학습목표에 맞춰 설명·사례·활동으로 바꿔 쓰는 것은 제작 단계(edu-create)의 일이다.

### 7. 제작 지시문 확정과 인계

모든 블록이 확정되고 조사 채택이 끝나면 `00_제작지시문.md`를 확정한다. 확인할 것:

- 본문의 시간·산출물·활동이 최신 결정과 일치한다(오래된 표현이 남지 않았다).
- 블록마다 채택한 조사 파일과 위치가 연결되어 있다.
- 미확인·보류·강사 결정 대기 항목이 목록으로 정리되어 있다. 이것들이 남아도 독립적으로 제작 가능한 부분은 `edu-create`가 진행할 수 있게 구분한다.

인계 완료 기준은 `edu-create`가 이 두 종류의 파일만으로 **무엇을 가르치고, 어떤 자료로 무엇을 만들게 하며, 무엇으로 판단하고, 어떤 근거를 쓰는지** 알 수 있는가이다. 마지막에 강사에게 `edu-create`에 넘기는 방법을 안내한다: "제작 지시문과 조사 결과 파일들을 함께 전달하고 '교안 제작해줘'라고 요청".

## 저장 구조

```
교육 폴더/
└── 설계/
    ├── 00_제작지시문.md          과정 개요·타임테이블·블록 카드·결정 이력·조사 채택 목록
    └── 조사/
        ├── B01_{블록 제목}.md    블록별 조사 결과 (타임테이블 순서와 같은 번호)
        └── B02_{블록 제목}.md
```

- 파일은 위 이름 규칙을 따른다. 파일을 저장할 수 없는 환경이면 같은 이름을 제목으로 붙여 대화에 제공한다.
- 새 저장 위치나 공유 공간을 임의로 만들지 않는다. 강사가 지정한 위치가 있으면 그 위치를 쓴다.
- 이 파일들은 **내부 설계 기록**이다. 수강생에게 배포하는 자료가 아니므로 `edu-create`가 수강생용 자료로 만들 때 강사용 메모와 섞이지 않게 한다.

## 결정 기록과 변경

- 결정은 항목별로 `확정 / 제안 / 미확인`과 근거(강사의 말·자료 위치)를 남긴다.
- 새 결정이 이전 안을 대체하면 이력은 보존하고 현재 본문·타임테이블·블록 카드·조사 채택 목록을 함께 맞춘다.
- 새 대화에서 이어갈 때는 강사가 붙여넣은 제작 지시문과 조사 파일을 읽고, 현재 상태·남은 결정·보류를 정리해 확인받은 뒤 이어간다. 파일에 없는 내용을 기억으로 이어 쓰지 않는다.
- `edu-create` 실행 뒤 설계가 바뀌면 이 스킬로 돌아와 지시문을 갱신하고 변경 위치를 알린다. 이미 만든 교안·실습 자료는 이 스킬이 직접 고치지 않는다.

## 상태와 보고 표기

- 구분해서 보고한다: 커리큘럼 확인 / 타임테이블 확정 / 블록 설계 / 조사 지시 작성 / 조사 결과 확보 / 근거 확인 / 지시문 확정. 한 상태가 다른 범위를 한꺼번에 완료로 만들지 않는다.
- "문제 없음"은 확인을 수행한 경우에만 쓴다. 확인하지 않은 항목은 `미검증`이다.
- 추정은 추정이라고 적는다. 예: "토론 20분 — 추정".
- 접속 키·비밀번호·개인정보를 파일이나 보고에 적지 않는다. 강사 내부 자료를 외부 서비스에 임의로 올리지 않는다.

## 완료 보고
