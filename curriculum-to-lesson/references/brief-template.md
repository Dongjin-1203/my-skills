# 제작 지시문 양식 (`00_제작지시문.md`)

`edu-create`가 이 파일을 읽고 교안과 실습 자료를 만든다. 아래 절을 기존 문서에 맞게 조합하며 불필요한 별도 파일은 늘리지 않는다. 학생 배포물이 아닌 내부 설계 기록이다.

`edu-create`가 읽는 필드와 이름을 바꾸지 않는다: **분야, 수강생, 타임테이블, 블록 카드, 조사 채택 목록, 미결정·미확인, 결정 이력**.

## 1. 과정 개요와 조건

```markdown
# 제작 지시문: {과정명} — 버전 {v1} / {작성일}

- 과정명·대상:
- 분야: {강사가 답한 분야} / 인용·표기 방식: {지정된 것 | 없음}
- 수강생: {직무·전공·수준·인원} (가정이면 가정이라고 표시)
- 궁극적 목적: 교육 후 수강생이 수행·판단할 수 있는 일
- 원안(커리큘럼)의 위치·버전: {파일명·절 | "질의응답으로 작성"}
- 원안에서 유지할 목표·주제:
- 최종 결과물과 성과 확인 방식:
- 요청 범위와 우선순위:
```

| 조건 | 현재 값 | 확정 / 제안 / 미확인 | 근거·영향 |
|---|---|---|---|
| 시작·종료·점심·휴식 | | | |
| 대면/온라인, 인원, 조 구성 | | | |
| 수강생이 쓸 도구·계정 (AI 도구 사용 여부 포함) | | | |
| 제공 가능한 자료(교재·사례·데이터) | | | |
| 수강생 자료 형식·제출 방식 | | | |

## 2. 전체 연결

| 블록 | 학습 행동 | 입력 | 최종 산출물 | 다음 블록에 넘길 것 |
|---|---|---|---|---|

앞선 결과가 다음 입력으로 재사용될 때만 연결한다. 독립적인 블록이면 연결을 억지로 만들지 않는다. 통합 활동에서 새 주제·자료·도구를 도입하면 추가 학습 부담을 점검한다.

## 3. 타임테이블

| 시작 | 종료 | 블록 / 휴식 / 점심 | 분 | 상태·근거 |
|---|---|---|---:|---|

- 총 가용시간과 블록·휴식·점심·공백 합계를 계산으로 맞춘다. 검산 과정을 한 줄로 적는다(예: 480 = 60+…).
- 추정치를 실제 수업 수행시간으로 쓰지 않는다.
- 이월·통합·축약 후보는 `미승인 후보`로 표시한다.

## 4. 블록 카드

블록마다 하나씩 쓴다. 블록 ID(B01, B02 …)는 타임테이블·조사 파일 이름과 같다.

```markdown
### B01 {블록 제목}
- 원안 요구사항과 근거 위치:
- 목적(왜 필요한가):
- 학생이 할 수 있게 될 일:
- 최종 산출물·필수 항목·완성 수준:
- 중간 작업물:
- 축약 완성 예시 / 잘못된 예:
- 제공 자료·이전 블록 결과:
- 설명·사례·시연 (각각 필요한 이유):
  - 설명: 
  - 사례: 
  - 시연: 
- 활동(토론·실습·과제) 수행 순서:
- 도구 사용(해당 시): 도구가 하는 일 / 학생이 선택·판단·수정할 일
- 확인 기준(목적 충족과 판단 이유를 보는 방법):
- 저장·제출·다음 블록 연결:
- 자료 대응: 교안 슬라이드 / 수강생 자료 / 강사용 자료
- 사용할 조사: {조사 파일 이름과 채택 항목 ID}
- 필요한 조사·준비물·미확인 조건:
- 결정 상태·근거: 확정 / 제안 / 미확인 — {강사의 말 또는 자료 위치}
```

| 활동 | 시간 | 측정 / 안내 / 추정 | 전제·지연 대응 |
|---|---:|---|---|
| 설명·사례·시연 | | | |
| 읽기·입력·수행(토론·실습) | | | |
| 처리·대기 (해당 시) | | | |
| 판단·수정·정리·발표 | | | |

블록 총시간, 활동 합계, 미배정 시간, 블록 밖 휴식을 각각 적는다. 대기 중 다른 활동을 하면 중복 합산하지 않고 겹치는 구간을 명시한다.

수강생이 볼 축약 예시와 강사용 전체 답안은 구분한다. 수강생 안내는 완성 예시 → 사용할 자료 → 수행 순서 → 확인 기준 → 저장·제출 순으로 구성할 수 있다.

## 5. 조사 채택 목록

| 조사 파일 | 항목 ID | 내용 요약 | 출처·확인 수준 | 채택 / 수정 / 보류 | 적용 블록·위치 |
|---|---|---|---|---|---|

- `edu-create`는 **채택·수정** 항목만 사실 근거로 쓴다. 보류 항목은 쓰지 않는다.
- 조사 파일에 없는 사실 정보는 `edu-create`가 쓰지 않거나 "확인 필요"로 표시한다.

## 6. 미결정·미확인

| 항목 | 영향받는 블록 | 상태 | 임시 처리 |
|---|---|---|---|

미확인이 남아도 독립적으로 제작 가능한 부분은 진행할 수 있도록 영향 블록을 구분한다.

## 7. 결정 이력

| 결정 ID | 항목 | 현재 내용·상태 | 강사 근거 | 대체한 결정 | 영향 위치·반영 상태 |
|---|---|---|---|---|---|

이력은 보존하고 현재 본문을 최신 결정으로 갱신한다. 확정 직전에 오래된 시간·형식·산출물 표현이 본문에 남았는지 대조한다.

## 8. 자체 점검 (설계 담당, 독립 검수 아님)

- 원안 목표마다 학습 행동과 확인 지점이 있는가?
- 학생이 산출물 예시와 제공 자료를 보고 시작할 수 있는가?
- 도구 사용 절차를 최종 산출물로 오인하지 않았는가?
- 학생의 선택·판단이 실제 과제에 포함됐는가?
- 수강생 안내와 강사용 예시가 같은 자료·과제·완성 수준을 쓰는가?
- 총시간과 활동 합계가 맞고 지연 대응이 있는가?
- 블록마다 사실 근거가 조사 채택 목록에 연결되어 있는가? 연결되지 않은 사실이 본문에 들어가 있지 않은가?
- 최신 결정, 제안, 미확인이 본문과 인계에서 일치하는가?

이 점검은 설계 담당의 확인이며 독립 검수 판정이 아니다.
