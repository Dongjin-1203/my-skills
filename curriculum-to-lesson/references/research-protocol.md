# 조사 절차와 조사 결과 양식

필요한 절만 사용한다. **조사 요청 작성**, **조사 실행**, **결과 회수·채택**, **설계 반영**은 서로 다른 단계이므로 한꺼번에 완료로 표시하지 않는다.

## 1. 분야별 조사 가이드

SKILL.md 단계 1에서 받은 분야 답변으로 해당 행을 채워 조사 과제 도출과 근거 판단에 쓴다. 표는 기본값이며 강사가 말한 용어·방식이 우선한다. 분야가 둘 이상이면 모두 적는다.

| 분야 | 우선할 근거 | 조사에서 얻을 것 | 출처 표기 | 특히 주의 |
|---|---|---|---|---|
| 인문(철학·문학·역사·언어) | 원전·1차 문헌, 학술 번역·주해서 | 핵심 개념 정의, 대표 논점, 연표, 원문 발췌 후보 | 저자·판본·쪽수. 번역서는 역자 | 번역·해석 차이를 구분. 원문 인용은 짧게·정확히 |
| 사회(심리·사회·교육·정치·법) | 학술 논문, 공식 통계, 법령·판례 원문 | 연구 결과, 사례, 통계 추이, 조항 | 연구자·연도·표본, 통계 기준 연도, 조항 번호 | 통계·판례·조항은 기억으로 쓰지 않음. 관점 균형 |
| 경영(경영·마케팅·회계·인사) | 기업 공시·보고서, 공식 발표, 신뢰할 만한 기사·교재 | 기업 사례, 프레임워크 정의, 시장 데이터 | 문서명·발행일·기준 시점 | 기업의 주장과 사실을 구분. 수치는 기준 시점 필수. 가상 사례 표시 |
| 기타 | 강사 답변에 따름 | | | |

강사가 이미 가진 자료(교재, 논문, 기사, 사내 자료)가 있으면 그것을 1순위 근거로 쓴다.

## 2. 조사 과제 목록

블록 카드에서 근거가 필요한 부분을 모아 만든다.

| 조사 ID | 적용 블록 | 해결할 질문 | 필요한 근거 | 사용할 형태 | 선행 자료 | 현재 상태 |
|---|---|---|---|---|---|---|

- 사용할 형태: 설명 근거 / 사례 카드 / 활동 자료 / 용어·정의 / 도구·환경 조건.
- 현재 상태: 요청 작성 / 실행 중 / 결과 확보 / 근거 확인 / 설계 반영 / 보류. 상태가 다른 범위를 한꺼번에 완료로 표시하지 않는다.
- 독립적으로 할 수 있는 조사와 선행 결과가 필요한 조사를 구분한다.

## 3. 조사 실행 방식

| 환경 | 처리 |
|---|---|
| 웹 검색·원문 열기 가능 | 직접 조사한다. 주장마다 URL·발행일 또는 확인일·근거 위치를 기록한다. 원문을 열어 확인하지 못한 것은 "미확인"으로 둔다 |
| 불가능 | 아래 **조사 지시문**을 작성해 강사가 검색 가능한 AI·도구에 넘기게 한다. 전달할 프롬프트를 쓴 것이지 조사를 실행한 것이 아니다 |
| 강사 자료만 있음 | 그 자료를 읽고 같은 양식으로 정리한다. 자료 밖의 사실은 추가하지 않는다 |

AI의 기억만으로 쓴 내용은 조사 결과가 아니다. 쓰더라도 `기억 기반 · 미확인`으로 표시하고 채택 대상에서 제외한다.

### 조사 지시문 (다른 AI·세션에 붙여넣을 프롬프트)

```text
다음 교육의 교안 설계에 필요한 조사를 수행해줘.

분야: {분야}
교육 맥락: 수강생 직무·수준, 궁극적 목적, 해당 블록의 목표와 산출물
해결할 질문: 조사할 질문과 우선순위
입력자료: 제공된 자료와 선행 조사 결과의 실제 본문 또는 첨부
조사 범위: 주제·지역·기간·버전 등 필요한 한정
제외 범위: 이번 교육에서 다루지 않을 심화 내용·활동
활용 형태: 설명 근거 / 사례 카드 / 활동 자료 / 용어 정의 중 필요한 것

공식 자료와 직접 확인 가능한 원문을 우선하고, 주장별 URL·발행일 또는 확인일·근거 위치·적용 조건을 기록해줘.
확인된 사실, 출처의 주장, 해석·가설, 교육용 창작을 구분해줘.
확인하지 못한 것은 추측으로 채우지 말고 "미확인"으로 적어줘.
내부 자료를 임의로 외부 서비스에 업로드하지 말고, 필요한 정보가 없으면 공백과 영향을 적어줘.

아래 형식의 Markdown으로 정리해줘:
(4절 '조사 결과 파일 형식'을 붙여넣는다)
```

도구별 내부 인용 기호만 남기지 않는다. 존재하지 않는 수강생 자료를 있는 것처럼 참조하지 않는다.

## 4. 조사 결과 파일 형식 (`조사/B01_{블록 제목}.md`)

블록마다 파일 하나다. 타임테이블 순서와 같은 번호를 쓴다. 한 파일에 여러 조사 질문을 담는다.

```markdown
# 조사 결과: B01 {블록 제목}
- 분야: / 적용 블록: / 조사 날짜: / 조사 방식: {직접 조사 | 지시문으로 위임 | 강사 자료 정리}
- 조사 환경: {웹 검색 가능 | 불가 | 강사 자료만}

## 1. 핵심 발견
- (3~5줄. 블록의 설명·사례·활동에 어떻게 쓰이는지)

## 2. 질문별 결과
### Q1. {해결할 질문}
- 답:
- 근거 항목: P1, P2

## 3. 주장·근거 표
| ID | 주장·사례 | 구분 | 출처(제목·저자·발행일/기준 시점·URL 또는 쪽수) | 근거 위치 | 적용 조건·한계 | 확인 수준 |
|---|---|---|---|---|---|---|
| P1 | | 사실 / 출처의 주장 / 해석 / 교육용 창작 | | | | 원문 확인 / 2차 자료 / 기억 기반·미확인 |

## 4. 이 블록에 쓸 설명·예시·활동 제안
- 설명:
- 사례:
- 활동:

## 5. 미확인·추가 확인 필요
- 항목과 영향

## 6. 출처 목록
- 직접 확인한 원문의 제목·URL(또는 서지 정보)
```

- `구분` 열에서 **교육용 창작**은 실제 사례처럼 쓰지 않는다. 가상이라고 밝힌다.
- 확인 수준이 `기억 기반·미확인`인 항목은 채택하지 않는다.

## 5. 결과 회수와 채택

1. 내용이 있는 실제 결과를 열어 요구한 질문에 답했는지, 핵심 원문이 있는지 확인한다. 빈 파일이나 지시문을 조사 결과로 취급하지 않는다.
2. 상충하는 내용은 조건·대상·시점 차이를 비교한다. 여러 AI의 동의를 사실 검증으로 간주하지 않는다.
3. 항목마다 결정한다.

| 주장·사례 ID | 출처·근거 위치 | 확인 범위 | 채택 / 수정 / 보류 | 적용 블록·위치 |
|---|---|---|---|---|

4. 확인할 수 없는 핵심 근거는 보류하고, 영향받지 않는 설계는 진행한다.
5. 채택·수정한 항목은 제작 지시문의 '조사 채택 목록'과 해당 블록 카드의 '사용할 조사'에 연결한다.
6. 조사 보고서를 그대로 교안으로 복사하지 않는다. 학습목표에 맞는 설명·사례·활동으로 바꾸는 일은 `edu-create`가 한다.

## 6. 파일로 저장할 수 없을 때

각 조사 결과를 `조사/B01_….md` 같은 파일명을 제목으로 붙인 코드 블록으로 대화에 제공한다. 강사가 같은 이름으로 저장해 두고, `edu-create`를 실행할 때 제작 지시문과 함께 붙여넣거나 첨부한다.
