# 검수 체크리스트와 검수 결과 형식 (education-review 전용)

각 항목의 결과는 `확인함(문제 없음)` / `지적` / `미검증(이유)` / `해당 없음(이유)` 중 하나로 남긴다.
근거 기준은 `references/standards.md`의 절 번호로 적는다.

## A. 과정 조건·검수 범위

- [ ] A1 시간표·차시 길이·학습목표·변경 가능 범위·수강생의 AI 도구 사용 여부·활동 환경을 원본 조건 자료에서 직접 확인했다. (standards §2)
- [ ] A2 진행안의 "과정 조건 요약"이 원본 조건 자료와 일치한다. 가정한 조건(수준 등)은 가정이라고 표시되어 있다.
- [ ] A3 조건 자료에 없는 내용을 확정된 조건처럼 쓰지 않았다.

## B. 흐름·학습목표·난이도

- [ ] B1 모든 학습목표가 최소 한 차시·활동과 연결된다.
- [ ] B2 활동에 필요한 선수 개념이 앞 차시·앞 슬라이드에 있다.
- [ ] B3 난이도가 수강생 수준(정보가 없으면 입문 수준 가정)에 맞다. 설명 없이 쓰인 전문 용어, 건너뛴 단계가 없다.
- [ ] B4 이월·축약 후보가 학습목표를 빠뜨리지 않는다. 변경 권한이 불명확한 후보가 "미승인 후보"로 표시되어 있다.

## T. 시간 배분

- [ ] T1 차시별 강의+활동 시간 합계를 직접 계산했고 차시 길이와 비교했다.
- [ ] T2 강의:활동 비율이 과정 조건(없으면 일반 기준 5:5~6:4)과 크게 어긋나면 이유가 있다. 강의·활동 단일 차시는 허용.
- [ ] T3 시간 추정에 근거가 있다(슬라이드 수, 활동 단계, 토론 인원·조 구성 등). 도구 실행 시간과 수강생 활동 소요시간 추정이 구분되어 있다.
- [ ] T4 분량 초과 차시에 이월안 또는 축약안이 있다.

## D. 자료 간 연결

- [ ] D1 진행안의 자료 위치(슬라이드 번호, 활동 번호, 파일명)가 실제 자료와 맞다. 슬라이드는 표시 순서 번호 기준.
- [ ] D2 활동 자료(사례·워크시트·과제)와 설명 슬라이드가 대응한다.
- [ ] D3 진행안에 언급된 자료·데이터·보조 파일이 모두 존재한다.

## E. 수강생용·모범 답안 정합성·실행

- [ ] E1 수강생용과 모범 답안이 같은 과제·같은 자료·같은 조건을 쓴다.
- [ ] E2 모범 답안·평가 기준이 수강생용 지시를 충족한다(지시에 없는 것을 요구하지 않고, 지시한 것을 모두 다룬다). 평가 기준(루브릭)이 과제 지시와 맞는다.
- [ ] E3 수강생이 AI 도구를 쓰는 수업의 수강생용이 지시사항 중심의 빈 양식 또는 Markdown이다. 상세도가 수준·학습목표에 맞다.
- [ ] E4 코드·수식·도구 실습이 있으면 모범 답안을 새 환경에서 처음부터 순서대로 실행했다. (해당 없음 또는 실행 기능 없으면 미검증)
- [ ] E5 수강생용에 제공된 코드·수식·템플릿(빈칸 외)이 실행된다. (해당 없음 또는 실행 기능 없으면 미검증)
- [ ] E6 실제 수업 환경(플랫폼·기기·제공 도구 계정)에서 검증했는가 — 대부분 "미검증"으로 남는다. 숨기지 않는다.

## F. 수강생 배포 기준·문체·화면·사실

- [ ] F1 강사 발화문·대본·진행 지시가 없다. (standards §8)
- [ ] F2 차시·일차 등 일정 종속 표현이 없다.
- [ ] F3 수업·활동 예상 진행시간이 없다. 학습 내용상 필요한 시간 수치는 남아 있다. (§9)
- [ ] F4 강사·조교 역할, 진도 대응 등 내부 운영 메모가 없다.
- [ ] F5 수강생에게 필요한 활동 지시가 삭제되지 않았다.
- [ ] F6 슬라이드 발표자 노트·댓글·숨김 슬라이드를 모두 확인했다. 문서의 주석·변경 추적·숨김 텍스트도 확인했다.
- [ ] F7 코드·노트북이 있으면 설명·주석·저장된 출력을 확인했다. 수강생용에 모범 답안·정답 출력이 없다. (해당 없음이면 그렇게 적음)
- [ ] F8 접속 키·비밀번호·개인정보·개인 로컬 경로가 없다. (발견 시 값은 가려서 보고)
- [ ] F9 링크: 문자열 확인 / 실제 접속 확인을 구분해 적었다.
- [ ] F10 화면 잘림·겹침·가독성을 렌더링으로 확인했다. (렌더링 기능 없으면 미검증)
- [ ] F11 문체: 상투적 도입·맺음, 반복 요약, 과도한 강조·이모지, 번역투. 문체 수정으로 의미가 바뀌지 않았다.
- [ ] F12 검수 대상 버전의 각 자료에 역할(수강생용·모범 답안용·강사용·관리용)을 지정했고, 수강생용 묶음에 모범 답안용·강사용·관리용이 섞이지 않았다. 모범 답안은 별도 묶음이다. 파일 이름이 아니라 내용과 역할로 판단했다(이름은 참고). (standards §13)
- [ ] F13 사실·출처: 인용·통계·이론·제도·기업 사례 수치가 강사 원본이나 표시된 출처와 일치한다. 수정 과정에서 새로 들어온 사실에 출처가 있거나 "확인 필요"로 표시되어 있다. 가상 사례가 실제 사례처럼 쓰이지 않았다. AI의 기억만으로 사실 여부를 판정하지 않았다. (standards §11)
- [ ] F14 균형: 민감한 주제(정치·종교·젠더·인종·특정 기업·개인)를 다룬 부분이 특정 관점을 사실처럼 단정하지 않는다.

## G. 승인 범위 준수 (수정본 검수)

- [ ] G1 승인된 수정 항목이 모두 반영되었다(수정 ID별).
- [ ] G2 승인 범위 밖 변경이 없다. 변경 종류(시간·이월·추가·삭제 등)가 아니라 승인 항목과 승인 상세에 들어가는지로 판단한다. 개정 기록의 근거 항목이 실제 승인 항목에 있고 변경 내용이 그 항목과 맞는다.
- [ ] G3 원본이 보존되어 있다(원본 이름·버전·식별 정보가 작업 메모 기록과 같다).
- [ ] G4 진행안의 자료 위치가 수정본 기준으로 갱신되었다.

## V. 기관 지정 템플릿 (해당할 때만)

지정 템플릿이나 양식이 없는 과정이면 V 전체를 "해당 없음"으로 적는다. 템플릿이나 규칙 설명에 접근하지 못하면 "미검증(이유)"으로 적는다. 규칙은 강사가 준 템플릿과 설명만을 근거로 하고, 짐작으로 기준을 만들지 않는다.

- [ ] V0 (진행안 검수) 기존 자료와 지정 템플릿의 차이가 수정 계획에 수정 ID로 들어 있고, 전체 재디자인이 승인 없이 계획되지 않았다.
- [ ] V1 올바른 템플릿 버전을 썼다: 작업본의 슬라이드 크기·마스터·레이아웃 이름이 강사가 준 템플릿과 맞는다.
- [ ] V2 마스터·레이아웃·테마·브랜드 요소(색, 배경, 로고, 저작권 표기, 쪽 번호)와 서식이 의도치 않게 바뀌지 않았다. 템플릿에 없던 글꼴 지정이나 임의 축소된 글꼴 크기가 없다.
- [ ] V3 템플릿에 글자 수 안내가 있으면 지켰다. "최대 두 줄" 같은 기준은 렌더링으로 확인했는가, 못 했으면 미검증.
- [ ] V4 작성 안내 문구, 빈 자리표시자, 예제 내용·샘플 수치·샘플 날짜가 남아 있지 않다. 예시 슬라이드가 필요 없이 통째로 들어가 있지 않다.
- [ ] V5 필요한 글꼴이 검수 환경에서 보이고, 실제 렌더링에서 잘림·겹침·글꼴 대체가 없다. 글꼴이 없거나 렌더링을 못 했으면 해당 부분은 "미검증"이다.
- [ ] V6 출처가 필요한 내용(인용·통계·외부 이미지·기사)에 실제로 확인 가능한 출처가 있다. 출처 영역의 안내 문구가 그대로 남아 있지 않다. 출처의 실재를 확인하지 못했으면 "출처 확인 필요"로 지적한다.
- [ ] V7 템플릿 슬라이드 안에도 강사 발화문·차시/일차 종속 표현·예상 진행시간·내부 운영 메모가 없다(F1~F4와 함께). 렉처 번호·챕터 번호는 의미를 보고 판단했다.

## 재검증 시 추가

- [ ] R1 이전 지적 ID별로 반영 여부와 반영 위치를 확인했다. 반박된 지적은 근거를 검토했다.
- [ ] R2 반영 과정에서 새로 생긴 문제를 확인했다(특히 수강생용·모범 답안 짝 수정 누락).
- [ ] R3 이전 미검증 항목의 현재 상태를 적었다.

# 검수 결과 형식

```markdown
# 검수 결과: {과정명} — {검수 종류} {회차}
- 검수일 / 검수 환경: {AI 이름 또는 "대화 전용", 기능 확인 요약(읽기·렌더링·실행 가능 여부)}
- 검수 결과 ID: {회차마다 고유. 작업 메모의 '검수·배포 판정'·'조건 수용'이 이 ID로 연결됨}
- 검수 대상 버전: {검수한 자료 전부의 이름·버전 라벨·식별 정보·**역할(수강생용·모범 답안용·강사용·관리용)**. 이 목록이 배포의 유일한 기준. 요청서와 다르면 차이를 먼저 적음}
- 판정 [제안]: {통과 | 조건부 통과 | 재작업 필요} — 이 판정은 위 검수 대상 버전에만 적용됨
- 미해결 높음 {n}건 / 보통 {n}건 / 미검증 {n}건

## 조건 (조건부 통과일 때만)
| 조건 ID(예: C1) | 내용 | 자료 수정 필요 여부(항상 "없음"이어야 함) | 강사 수용 필요 |
|---|---|---|---|

## 지적 사항 (중요도 높음 → 보통 → 낮음 순)
| ID | 중요도 | 위치 | 근거(기준 문서 절 또는 원본 위치) | 문제 | 수정 제안 | 범위 판단 | 검증 수준 |
|---|---|---|---|---|---|---|---|

## 확인했으나 문제 없는 항목
- 항목과 검증 수준 (수행한 것만)

## 미검증 사항
| 항목 | 이유(기능 없음·접근 불가·정보 부족·실제 수업 환경 없음) | 필요한 조건 |

## 판단이 필요한 사항 (강사에게)
```

- **위치**는 자료 이름 + 슬라이드 번호(노트·댓글·숨김 여부) 또는 문서의 쪽·절 또는 코드·노트북 셀 번호 또는 차시 행으로 적는다.
- **중요도** [제안]:
  - 높음: 수업 진행이나 배포에 직접 문제 (모범 답안 노출, 접속 키·개인정보, 사실 오류, 학습목표 누락, 시간 대폭 초과, 승인 범위 밖 변경, 실행 실패)
  - 보통: 혼선 가능 (일정 종속 표현, 수강생용·모범 답안 불일치, 선수지식 순서, 화면 잘림, 출처 없는 사실)
  - 낮음: 형식·문체 (상투적 표현, 표기 불일치)
- **범위 판단**: `승인 범위 내 수정 가능` / `새 판단 필요` / `범위 밖`.
- 판단이 애매하면 누락하지 말고 지적하되, 왜 애매한지 문제 칸에 적는다. 자료에 실제로 있는 내용만 근거로 삼는다.
- 지적 사항이 없으면 "지적 사항 없음"과 함께 수행한 검사 범위를 적는다. 수행 범위 없이 "문제 없음"만 적지 않는다.
- [제안] **판정 정의** (세부 기준은 실제 과정 시험 후 확정):

  | 판정 | 의미 | 배포 |
  |---|---|---|
  | 통과 | 해결되지 않은 `높음`·`보통`이 없고, 필수 검사(수강생용·모범 답안 정합성, 배포 기준, 사실·출처)에 미검증 항목이 없음 | 검수 대상 버전 그대로면 가능 |
  | 조건부 통과 | 해결되지 않은 `높음`이 없고, 남은 것이 **자료를 고치지 않고 강사 수용만으로 끝나는 조건**(예: 실제 수업 환경 미검증, 남겨 두기로 한 `보통`)뿐임. 조건마다 조건 ID를 붙임 | 모든 조건의 강사 수용이 기록된 뒤에만, 검수 대상 버전 그대로면 가능 |
  | 재작업 필요 | 자료 수정이 필요한 지적이 하나라도 있거나 `높음`이 남음 | 불가. 수정 후 재검증에서 새 판정을 받아야 함 |

  이유: 미검증이나 남은 문제를 통과로 흡수하지 않고, "조건부"가 어떤 조건에서 배포로 이어지는지 판정 단계에서 정해 두기 위해서다. 자료 수정이 필요한 조건을 "조건부 통과"로 적지 않는다. 고친 자료는 검수받지 않은 새 버전이기 때문이다.
