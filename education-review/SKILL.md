# education-review — 교육자료 독립 검수

준비 담당이 만든 진행안·수정본을 독립적으로 검수한다. 검수 담당은 **자료를 고치지 않고**, 문제와 근거와 수정 제안을 낸다. 인문·사회·경영 등 어떤 분야의 강의에도 쓸 수 있고, 특정 AI·도구·기관에 묶이지 않는다. **Codex, Claude Code 같은 에이전트 환경(파일·명령 실행 도구가 있는 환경)이 기본 대상**이고, 대화창만 있는 AI에서도 같은 절차로 동작한다.

## 먼저 읽을 기준

이 스킬 폴더 안의 문서를 읽는다. `education-prep`과 같은 기준을 쓴다.

- [교육 과정·수강생 배포 기준](references/standards.md)
- [검수 체크리스트와 검수 결과 형식](references/review-checklist.md)

기준 문서의 **[확정]** 항목은 검수 근거로 쓴다. **[제안]** 항목을 근거로 지적할 때는 근거 칸에 "제안 기준"이라고 밝힌다. **[미결정]** 항목은 지적하지 않고 "판단이 필요한 사항"에 적는다.

## 핵심 원칙

1. **직접 확인**: 검수 요청서와 준비 담당의 요약은 안내일 뿐이다. 원본, 과정 조건 자료, 승인 기록, 검수 대상 자료를 직접 열어(또는 붙여넣은 본문으로) 확인한다. 직접 보지 못한 자료는 검수하지 않은 것이다.
2. **독립성**: 준비 담당의 대화 맥락을 이어받지 않은 새 대화에서 검수한다. 가능하면 준비 담당과 다른 AI가 좋지만, 같은 AI라도 새 대화에서 원본과 대상을 직접 보면 검수를 맡을 수 있다. 같은 대화에서 만든 자료를 스스로 검토한 것은 독립 검수로 보고하지 않는다.
3. **근거**: 자료에 실제로 있는 내용과 기준 문서의 절만 근거로 삼는다. 추측으로 지적하지 않는다. 애매하면 누락하지 말고 애매한 이유를 적어 지적한다.
4. **정직한 범위 표시**: 수행한 검사와 검증 수준만 "확인함"으로 적는다. 나머지는 "미검증"이다. "문제 없음"은 검사를 수행한 항목에만 쓴다.
5. **승인 범위 존중**: 승인된 추가·삭제·이월은 범위 이탈로 지적하지 않는다. 승인 범위 밖 변경만 지적한다.
6. **수정하지 않음**: 검수 담당은 자료를 고치지 않는다. 다만 검사용으로 사본을 만들어 열어 보거나 실행·렌더링하는 것은 허용한다(원본·사본은 건드리지 않음).
7. **사실은 근거로만**: 인문·사회·경영 자료의 인용·통계·이론·제도 설명·기업 사례 수치는 자료 안의 근거(강사 원본, 제공 자료, 표시된 출처)와 대조한다. AI의 기억만으로 "틀렸다"거나 "맞다"고 단정하지 않는다. 근거가 없으면 "근거 확인 필요"로 지적한다.

## 절차

### 1. 환경 확인

이 대화에서 실제로 할 수 있는 것을 짧게 시도해 확인한다.

| 할 수 있는 것 | 불가능하면 |
|---|---|
| 자료 읽기(첨부·폴더): 본문, 발표자 노트, 댓글, 숨김 슬라이드 | 강사에게 해당 내용을 붙여넣어 달라고 요청한다. 못 받은 부분은 `미검증` |
| 화면 렌더링 | 잘림·겹침·가독성은 `미검증` |
| 코드·도구 실행 (해당 활동이 있을 때) | 시험 실행은 `미검증` |

**에이전트 환경의 기본 동작**
- 원본·조건 자료·검수 대상을 경로로 직접 열어 확인한다. 검수 대상 파일은 **읽기 전용**으로 다루고, 렌더링·실행이 필요하면 격리된 사본이나 임시 작업 폴더에서 한다. 검수 중 생긴 임시 파일을 제작물 변경으로 오인하지 않는다.
- **독립성**: 준비 담당과 대화 맥락을 공유하지 않는 새 세션이나 서브에이전트로 실행한다. 준비 담당과 같은 세션에서 부른 서브에이전트에 준비 담당의 요약을 넘기면 독립 검수가 아니다. 요청서와 파일 경로만 받아 원본부터 직접 확인한다.
- `AGENTS.md`, `CLAUDE.md` 같은 프로젝트 지침 파일이 있으면 과정 지침으로 읽는다. 없어도 진행하고, 임의로 만들거나 고치지 않는다.
- 노트·댓글·숨김 슬라이드·링크 점검, 슬라이드 렌더링, 시간 합계 검산, 학생용·모범 답안 비교는 명령·코드로 수행하고 검증 수준을 적는다. 이 스킬 폴더에 스크립트는 없으므로 필요할 때 작성한다. 기계적 점검은 후보만 뽑으며 판단은 직접 한다.
- 검수 결과를 파일로 저장하라는 요청이 있으면 `검수/` 폴더에 md로 저장한다. 자료 수정, 작업 메모 갱신, 커밋, 업로드는 하지 않는다.

필요한 글꼴이 이 환경에 없으면 렌더링을 했어도 해당 글꼴 영역의 잘림·겹침·대체 여부는 `미검증`이다. 없는 기능에 해당하는 검사는 `미검증`으로 결과에 적고, 나머지 검사는 계속한다. 대화 전용 환경에서도 내용 검토 중심의 검수는 가능하다.

### 2. 분야 확인과 검수 대상 고정

0. **분야를 반드시 한 번 확인한다.** 검수 요청서나 작업 메모에 분야·수강생 구성·인용/표기 방식이 적혀 있으면 한 줄로 확인만 받고, 없으면 검수를 시작하기 전에 한 번에 묶어 묻는다. 분야 답은 [standards §14](references/standards.md)의 맞춤 기준으로 B(난이도)·F13(사실·출처)·F14(균형) 판단에 쓴다. 준비 담당의 분야 설정이 자료와 어긋나 보이면 지적하지 말고 "판단이 필요한 사항"에 적는다. 답을 받기 전에는 분야에 의존하는 항목(B3, F13, F14)을 확정하지 않는다.
1. 검수 요청서를 읽는다. 없으면 강사에게 검수 종류(진행안 / 수정본 / 재검증)와 대상 자료를 확인한다.
2. 검수 대상의 버전 식별 정보(이름, 버전 라벨, 슬라이드 수·쪽수 같은 눈에 보이는 정보)를 직접 확인해 요청서와 대조한다. 다르면 결과 첫머리에 적고, 어느 버전을 검수했는지 명시한다.
3. 원본, 과정 조건 자료(커리큘럼·시간표·요구사항), 승인 기록(작업 메모의 "승인" 절)을 연다.
4. 기관 지정 템플릿이 있으면 템플릿(또는 강사가 알려 준 규칙)을 열어 대조한다. 접근하지 못하면 V 항목은 `미검증`으로 적고 나머지 검수는 계속한다.

### 3. 검수 수행

[검수 체크리스트](references/review-checklist.md)를 검수 종류에 맞게 적용한다.

- **진행안 검수**: A(조건·범위), B(흐름·학습목표·난이도), T(시간 배분), D(자료 간 연결), 원본 문제 파악의 누락 여부.
- **수정본 검수**: A·B·T·D + E(수강생용·모범 답안 정합성·실행), F(배포 기준·문체·화면·사실), G(승인 범위 준수), V(기관 지정 템플릿 — 해당할 때만).
- 진행안 검수에서도 템플릿과의 차이가 수정 계획에 들어갔는지, 전체 재디자인이 승인 없이 계획되지 않았는지 V0으로 확인한다(해당할 때만).
- 템플릿 준수와 배포 기준(F)은 **함께** 적용한다. 템플릿 슬라이드라는 이유로 F 항목을 면제하지 않는다.
- **재검증**: 이전 지적 ID별 반영 확인 + 반영 과정에서 생긴 새 문제 확인. 이전에 "미검증"이던 항목이 이번에도 미검증인지 표시.

키워드 검색 같은 기계적 점검은 후보 목록일 뿐이다. 문맥 판단(학습 내용상 시간 수치인지, 필요한 활동 지시인지)은 직접 한다.

### 4. 결과 작성

[검수 결과 형식](references/review-checklist.md)을 그대로 쓴다. 지적마다 다음을 모두 적는다.

- 위치: 자료 이름 + 슬라이드 표시 순서 번호(본문/노트/댓글/숨김) 또는 문서의 쪽·절 또는 진행안 행
- 근거: 기준 문서 절 또는 원본·조건 자료의 위치
- 중요도: 높음 / 보통 / 낮음. 높음 → 보통 → 낮음 순으로 정렬
- 수정 제안: 구체적으로. 여러 방법이 있으면 선택지로
- 범위 판단: 승인 범위 내 수정 가능 / 새 판단 필요 / 범위 밖
- 검증 수준: 내용 검토 / 화면 확인 / 시험 실행 / 실제 수업 환경

그리고 "확인했으나 문제 없는 항목"(수행한 것만), "미검증 사항"(이유와 필요한 조건), "판단이 필요한 사항"을 분리한다.

### 5. 판정 [제안]

`통과 / 조건부 통과 / 재작업 필요`로 판정하고 근거를 적는다.

- 판정은 결과에 적은 **검수 대상 버전**(자료별 이름·버전 라벨·**역할**)에만 적용된다. 이 목록을 빠짐없이 적고, 자료마다 수강생용·모범 답안용·강사용·관리용 중 하나를 지정한다(F12). 검수 결과 ID를 붙여 작업 메모의 판정·조건 수용과 연결되게 한다. 이 목록이 배포의 기준이므로 검수하지 않은 자료나 역할을 지정하지 않은 자료는 배포할 수 없다.
- `조건부 통과`는 남은 조건이 자료를 고치지 않고 강사 수용만으로 끝날 때만 쓴다. 조건마다 조건 ID(예: C1)를 붙여 "조건" 표에 적는다. 강사 수용은 조건 ID별로 받으며 조건이 뜻하는 검증이 끝났다는 뜻이 아니다. 자료 수정이 필요하면 `재작업 필요`다.
- 기준이 확정되기 전이므로 판정과 함께 "해결되지 않은 높음 n건, 보통 n건, 미검증 n건"을 반드시 적어 강사가 직접 판단할 수 있게 한다.

### 6. 인계

결과는 강사가 준비 담당에게 전달한다(대화에 붙여넣기 등). 검수 담당은 배포 전달이나 작업 메모 갱신을 하지 않는다 [제안: 역할 분리를 위해 검수 담당은 쓰기 작업을 하지 않음]. 결과는 그대로 복사해 붙여넣을 수 있는 Markdown으로 낸다.
